# Arklock — текущее состояние проекта

Последнее обновление: 2026-10-23. Версия в VERSION и пакетах: **1.31.0**. Состав выпуска описан в CHANGELOG → 1.31.0.

## Назначение и архитектура

Корпоративный менеджер паролей для самостоятельного размещения, AGPL-3.0-only. Нет платных ограничений, лицензионных ключей и телеметрии лицензирования.

Node.js 24, TypeScript, npm workspaces; Fastify + Drizzle + PostgreSQL/PGlite; Vue 3 + Pinia + Tailwind. Клиентское шифрование WebCrypto и Argon2id в Worker. Учётные записи, сейфы, группы, роли, объектные назначения, зашифрованные записи/вложения и журнал ключей используют существующую схему без удаления пользовательских данных.

## Реализованные основные возможности

- Учётные записи, активация кодом, мастер-пароль и персональный ключ восстановления; MFA TOTP/WebAuthn, LDAP, OIDC/SAML, сеансы.
- Корпоративные сейфы, папки, записи, файлы/TOTP, избранное, архив, корзина, ревизии, импорт/экспорт, передача по внешней ссылке.
- Административные и сейфовые роли, прямые и групповые назначения, сроки, наследование и серверный приоритет явных запретов объектов.
- Корпоративный сейф первого администратора. Личные сейфы запрещены по умолчанию, разрешаются организации/пользователям/группам; прежние данные сохраняются. Управление и инвентаризация доступны в админке.
- Корпоративные пространства поверх сейфов: общие и закрытые, участники и группы, архив и перенос сейфов. Членство не заменяет выдачу ключа; прежние общие сейфы автоматически попадают в Organization.
- Действующие вкладки записи «Данные / Доступ / Журнал / Настройки»; доступ, журнал и политика папок; политика сейфа. Доступ показывает источники полномочий и ожидание выдачи ключа.
- Автоматическая подписанная выдача ключей разблокированным уполномоченным участником, отдельная ротация, передача владения.
- Проверка хранителей корпоративного ключа, предупреждение перед отключением единственного хранителя с возможностью явно подтвердить риск срочного отзыва.
- Явное корпоративное восстановление: зашифрованный офлайн-пакет, подключение каждого сейфа, одноразовый запрос с подтверждением владения ключами, восстановление владельца и аудит. Подключение сохраняется при ротации ключа сейфа.
- Несколько LDAP-профилей с выбором при входе, просмотром пользователей/групп/OU, сопоставлением групп, ручной и плановой сверкой каждые 6 часов; изоляция каталогов и немедленный отзыв сеансов при отключении.
- Локальный инспектор и приватная проверка утечек (до пяти провайдеров формата HIBP range, SSRF-защита, k-anonymity, объединение ответов). Незавершённая проверка не считается успешной.
- Разблокировка после F5 без мастер-пароля: доля ключа в сеансе на сервере + шифртекст во вкладке (`routes/session-reload.ts`, `services/reload.ts`, `security.reloadUnlock`, docs/security/session-reload.md); передача сеанса новой вкладке через BroadcastChannel; ручная блокировка — во всех вкладках.
- Повышенное подтверждение по уровню риска (`services/stepup.ts`, 15 минут, общее для всех экранов); штатное обновление без него.
- Единое окно «Предоставить доступ» (`GrantDialog.vue`) для сейфа, папки и записи.
- Быстрая разблокировка PIN-кодом (выкл. по умолчанию; доля ключа на сервере, 5 попыток; docs/security/pin-unlock.md).
- Вебхуки с подписью HMAC (docs/administration/webhooks.md).
- Веб-панель системы, несколько SMTP-профилей и очередь писем, центр уведомлений, syslog, диагностика, расписание/удалённые копии, загрузка и восстановление копий, обновления/откат через отдельный помощник.
- Административные роли назначаются пользователям и группам (в том числе доменным); права суммируются, действуют только пока человек в группе; состав таких групп меняет лишь полный администратор.
- Увольнение сотрудника (`/admin/users/:id/offboarding`, `/offboard`): передача владения, блокировка, завершение сеансов, снятие прав и токенов, список сейфов для ротации ключа.
- Система оформления «точный инструмент»: токены поверхностей и движения в `apps/web/src/style.css`, шрифты Onest и JetBrains Mono (`@fontsource-variable/*`, OFL-1.1, разрешены проверкой лицензий только для шрифтов), компоненты `ActionMenu`, `SecretText`, `IconButton`. Шрифты не встраиваются в CSS (CSP запрещает data:-шрифты).
- Единый словарь терминов RU/EN (проверяется тестом `apps/web/test/i18n.test.ts`), компонент подсказки `InfoHint.vue`, страница `/help`, человеческие сообщения об ошибках (`errorMessage` в `services/helpers.ts`); имя корпоративного сейфа «Organization» показывается локализованным (`vaultLabel`, `spaceLabel`).
- Публичный адрес задаётся в панели (`system.publicUrl`, `public-url.ts`, `routes/admin-network.ts`, «Настройки → Сеть и доступ»), главнее `APP_PUBLIC_URL`, без перезапуска. Обзор обновлений сравнивает найденную версию с работающей по SemVer (`semverGreater`); версия интерфейса зашита в сборку (`__APP_VERSION__`).
- Прежний личный сейф: предупреждение только при наличии записей, закрывается насовсем (`users.dismissed_notices`); сотрудник удаляет свой сейф сам с мастер-паролем (`/auth/personal-vault/erase`).
- Главный администратор (`users.chief`, уникальный частичный индекс; `routes/chief.ts`): назначение полных администраторов, передача роли с подтверждением преемника мастер-паролем, обзор организации `/admin/structure`. Повторное подтверждение — общая `requireReauth` в `auth/reauth.ts`.
- Карточка сотрудника: `users.title/department/phone/profile_source`, синхронизация из LDAP `syncProfileFor` (`auth/ldap-sync.ts`), правка `PATCH /admin/users/:id/profile`.
- Журнал: событие `entry.client.open`, поиск в журнале объекта, имена и поиск по сотруднику в `/admin/ledger`, подписи всех действий (`ledgerAction` в `i18n/help.ts`).
- Состав установки (`inventory.ts`, `/admin/updates/inventory`, раздел «Компоненты установки»), SBOM к выпуску; пробное восстановление копии (`backup.sh --restore-test`, кнопка «Проверить»); диагностика кодами состояний (`DIAGNOSTIC_STATES` в contracts), тексты RU/EN в словаре.
- CLI, токены API, расширение Chromium/Firefox, PWA и адаптивный интерфейс.

## Размещение и эксплуатация

Установка: Ubuntu 22.04/24.04 LTS, Debian 12. Программа — /opt/arklock, настройки — /etc/arklock/arklock.env, ключ резервного шифрования — /etc/arklock/backup.key, данные — /var/lib/arklock и том PostgreSQL. Адрес/порт задаются APP_BIND/APP_PORT, HTTPS через установщик или существующий reverse proxy. Другие Docker-проекты не затрагиваются.

Существующие install.sh, scripts/{backup,restore,update,rollback,diag,status}.sh и конвейеры CI/Release сохранены.

## Проверка текущего блока

Адресные API/web-проверки, полная сборка, типы, линтер, формат, миграции и браузерные экраны проверены. Фактические результаты — HISTORY.md. Полный инфраструктурный CI и обновление старых серверов выполняются после отправки выпуска.

## Открытые ограничения

- Живой сценарий обновления в CI однажды упал без установленной причины (проверка статуса удалённой версии осталась прежней); при повторении разбирать по трассе.
- Запреты объектов действуют на сервере. Общий ключ сейфа не даёт криптографической изоляции одной записи от участника, сохранившего ключ и шифртекст. Для такой изоляции сейчас нужны разные сейфы.
- Корпоративное восстановление работает только для заранее подключённых сейфов с актуальным пакетом ключа. Получатель один; его можно отключить или заменить процедурой подготовки нового пакета и переподключения сейфов.
- Сервер не может самостоятельно выдать ключ без клиента уполномоченного участника. Сложность пароля проверяет веб-клиент; сторонний клиент способен обойти проверку открытого содержимого.
- LDAP: предварительное создание аккаунтов без клиентского формирования ключей не выполняется; пользователь подключается при первом входе. Нет SCIM и автоматического переноса идентичности после изменения DN; просмотр ограничен, расписание фиксировано.
- Шаблоны почты ограничены текстовыми сообщениями; полноценного конструктора HTML нет. Правила автоматизации не реализованы; PIN-схема не проходила независимой проверки. Вебхуки без очереди на диске: перезапуск прерывает повторы.
- Не проверены независимым аудитом криптография и продукт целиком; публикация расширений в магазинах и нативные мобильные приложения отсутствуют.
