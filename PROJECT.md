# Arklock — текущее состояние проекта

> Только актуальное состояние. Журнал изменений — HISTORY.md, изменения для пользователей — CHANGELOG.md.
> Последнее обновление: 2026-10-11

## 1. Назначение

Arklock — бесплатный корпоративный менеджер паролей с открытым исходным кодом, ориентированный на безопасность, самостоятельное развёртывание и централизованное управление доступом.
Репозиторий (цель публикации): https://github.com/calleograph/arklock — **пока не опубликован**.
Запрещены платные ограничения, лицензионные ключи, проверка подписки, привязка к внешнему серверу лицензий.

## 2. Статус

Этап 1 (каркас) выполнен. Этап 2 (учётные записи, мастер-пароль, клиентское шифрование, личный сейф) **реализован и проверен автотестами и сквозными тестами в настоящем браузере**. Остаются вне Этапа 2: общие хранилища, роли, история ревизий, корзина с восстановлением, поиск за пределами списка, импорт/экспорт, вложения (Этапы 3–4). Прототип **не пригоден для хранения реальных секретов**: криптографическая архитектура не проходила независимую проверку.

## 3. Технологии

Node.js 24, TypeScript 5.9 strict (ESM), npm workspaces. Backend: Fastify 5, Zod 4, Drizzle ORM (миграции drizzle-kit), PostgreSQL 16 (прод) / PGlite (разработка и тесты). Frontend: Vue 3, Pinia, Vue Router 4, vue-i18n 11, Vite 8, Tailwind CSS 4. Криптография: WebCrypto + Argon2id (`hash-wasm`). Тесты: Vitest 4, Playwright. Качество: ESLint 9, Prettier, vue-tsc. CI: GitHub Actions. Контейнеры: Docker, Compose.

## 5. Конфигурация (переменные окружения API)

`DATABASE_URL` (обязательна: `postgres://…` или `pglite:memory|pglite:<каталог>`), `APP_SECRET` (обязателен, ≥32 символов; не ключ шифрования данных), `PORT` (8080), `HOST`, `LOG_LEVEL`, `WEB_DIST`, `TRUSTED_PROXY_HOPS` (1), `SESSION_IDLE_HOURS` (12), `SESSION_MAX_DAYS` (7), `LOGIN_MAX_ATTEMPTS` (10), `LOGIN_WINDOW_MINUTES` (15), `UPDATE_CHANNEL` (stable|edge), `APP_VERSION`/`APP_GIT_COMMIT`/`APP_BUILT_AT` (задаёт сборка). Для compose: `POSTGRES_PASSWORD`, `APP_SECRET` (обязательны), `APP_PORT`, `COMPOSE_PROJECT_NAME`. Неверная конфигурация — отказ запуска с перечнем ошибок. Миграции применяются при старте. Режим регистрации — настройка `registration.mode` в таблице `settings` (`open`); по умолчанию после первой (администраторской) записи регистрация закрыта.

## 6. Реализовано

- **Криптоядро** (`@arklock/crypto`, 18 тестов): иерархия мастер-пароль → Argon2id → HKDF (раздельные ключи шифрования и входа) → закрытый ключ аккаунта (ECDH P-256) → ключ хранилища (запечатан каждому участнику) → ключ записи; контекст шифрования с однозначным кодированием; ключ восстановления с контрольной суммой; смена пароля без перешифровки данных; ротация ключа хранилища; реализация Argon2id сверена с эталоном OpenSSL (вектор RFC 9106).
- **API** (30 тестов): регистрация (первый — администратор, далее по политике), вход с ограничением попыток по адресу и IP (одинаково для несуществующих учётных записей), правдоподобные параметры для неизвестных адресов, сессии (хэш токена в БД, простой и абсолютный срок, список, отзыв), смена пароля, восстановление доступа, личный сейф, записи с оптимистичной блокировкой (409 при конфликте) и контролем версии ключа, мягкое удаление, 404 вместо 403 для чужих хранилищ, журнал Ledger без секретов, единый формат ошибок без эха входных данных, заголовки безопасности, маскирование журналов.
- **Веб-клиент**: регистрация с показом ключа восстановления (один раз, с подтверждением), вход, разблокировка (перезагрузка стирает ключи из памяти), автоблокировка через 5 минут, список и редактор записей, поиск, генератор паролей (CSPRNG), копирование с автоочисткой буфера через 30 с, сеансы и смена мастер-пароля, восстановление доступа, ru/en, светлая/тёмная тема.
- **Сквозные тесты в браузере** (Playwright, 2 сценария; локально — Microsoft Edge): весь пользовательский путь; проверено, что мастер-пароль, пароль, название и логин записи не попадают в тела запросов, нарушений CSP нет.
- Сканеры: частные данные и секреты (файлы и история), лицензии зависимостей (только разрешительные).

## 7. Не проверено / ограничения

- **Docker не установлен на машине разработки**: `Dockerfile`, `compose.yaml` и job `container` в CI не запускались. Контейнерное развёртывание нельзя считать работающим до первого успешного прогона.
- PostgreSQL проверен только через PGlite; прогон на PostgreSQL 16 — в CI.
- CI не запускался (репозиторий не опубликован).
- Независимая проверка криптографии не проводилась; известные слабые места и план — `docs/security/cryptography.md` (подмена открытых ключей сервером и неаутентифицированная отправка — актуально для общих хранилищ, Этап 4).
- Лицензия не выбрана (оценка — `docs/development/licensing.md`); файла LICENSE нет намеренно.
- Ограничитель попыток входа работает в памяти процесса (один экземпляр API).
- Argon2id выполняется в основном потоке браузера (около секунды) — перенос в Web Worker запланирован.
- Не реализованы: доступ по ролям к общим хранилищам, корзина с восстановлением, история ревизий, вложения, импорт/экспорт, MFA, LDAP/OIDC/SAML, административная панель, update-agent, резервное копирование, проверка скомпрометированных паролей.
