# UX-аудит внедрения в компании на 20 подразделений

Документ ведётся по ходу работы: каждый блок добавляет в таблицы «было → стало» измеренные значения.

## Методика

- Стенд: изолированная установка Arklock (`node apps/api/dist/main.js`, база в памяти, порт 18190), Chromium через Playwright, русский интерфейс.
- Организация: главный администратор, 20 руководителей (`head01…head20@corp.example`) и 40 сотрудников (`staff01…staff40@corp.example`), 20 подразделений из списка задания. Всё синтетическое.
- Сотрудники регистрируются по HTTP клиентом с настоящими ключами и настоящими параметрами KDF (так делает браузер); подразделения, права и работа создаются **через интерфейс** в браузере, структура проверяется независимо по API.
- Счётчик действий (`e2e/support/org.ts`, класс `Counter`): **нажатие** и **ввод/выбор** считаются по одному, **экран** — смена раздела или окна. Время — это время автоматизированного прохода (человек медленнее), оно годится для сравнения «до / после», а не как оценка скорости человека.
- Сценарии: `e2e/enterprise.spec.ts` (проект `enterprise`). Сырые измерения: `test-results/ux-measure.jsonl`.

## Рекомендуемая модель организации

Три варианта (пространство на отдел / сейф на отдел внутри общего пространства / корневая папка на отдел) не смешиваются; выбран **один**:

> отдел = **группа** + закрытое **пространство** + **сейф отдела** (роль «редактор» у группы) + при необходимости **отдельный сейф руководства**.

Почему так:

- Границы доверия — это сейфы. Ключ сейфа расшифровывает всё его содержимое, поэтому «папка для руководителей» в общем сейфе скрывает записи интерфейсом, но не криптографически. Руководству нужен **отдельный сейф**, а не папка.
- Пространство даёт отделу собственный список сейфов и своего управляющего (руководитель — администратор пространства), не затрагивая остальных.
- Группа — единственное место, где перечислены сотрудники: перевод и увольнение меняют состав группы, а доступ к сейфам следует за ней.
- Поиск работает по всем доступным сейфам, поэтому отдельные пространства его не усложняют.

Эта модель создаётся одним действием (мастер «Подразделения», раздел «Люди → Подразделения»).

## Сценарий 1. Создание подразделения

| Показатель | Было (прежний путь) | Стало (мастер) |
| --- | --- | --- |
| Действий всего | 34 (нажатий 24, вводов 10) | 6 (нажатий 4, вводов 2) |
| из них «пройти в раздел» | 7 | 3 |
| Экранов | 5 | 1 |
| Время автоматизированного прохода | 6,2 с | 2,3 с |
| Повторный ввод одного названия | 4 раза (группа, пространство, сейф, поиск группы при выдаче прав) | 1 раз |
| Действий на подразделение при списке из 19 | 34 × 19 = 646 | 3 на весь список |

**Было.** Для отдела приходилось по очереди: создать группу и добавить руководителя (раздел «Группы»), создать пространство и добавить в него группу (меню «Управление пространствами»), выбрать это пространство и создать сейф, открыть настройки сейфа и дважды вызвать окно «Предоставить доступ» (группе и руководителю). Четыре раздела, одно и то же название вводится четыре раза, ошибку в середине не видно до конца.

**Проблема.** Типовая операция внедрения — «завести отдел» — требовала знания внутреннего устройства (чем пространство отличается от сейфа и группы) и 30+ действий.

**Изменение.** Мастер «Подразделения» использует существующие сущности (группа, пространство, сейф, права) и последовательно вызывает существующие точки API; новой модели данных нет. Есть режим списка («Название; почта руководителя» по строке) с предпросмотром: что создаётся, что уже есть, какие конфликты (нет названия, повтор, руководитель не найден). Существующее используется повторно, поэтому после сбоя можно запустить тот же список ещё раз.

**Стало.** 6 действий для одного отдела, 3 — для списка (50 с на 19 отделов в автоматизированном прогоне). Повтор списка не создаёт дублей (проверено: в системе по 1 группе, пространству и сейфу на каждый из 20 отделов).

Проверка: `e2e/enterprise.spec.ts`, независимая проверка структуры по API в том же сценарии.

## Сценарии 2–5. Руководитель отдела: папки, запись, копирование, доступ

Проход в браузере руководителем отдела «Бухгалтерия» (вход, структура из пяти уровней, запись, копирование, выдача доступа другому отделу). Замеры — до исправлений 1.61.

| Действие | Действий | Экранов | Комментарий |
| --- | --- | --- | --- |
| Создать подпапку внутри выбранной папки | 4 (выбрать папку, «Новая папка», название, «Создать») | 0 | форма открывается одним нажатием внутри выбранной папки; цель «1 действие для открытия формы» выполнена |
| Создать запись в открытой папке | 6 с выбором папки; 5 без него | 1 | «Добавить запись», название, логин, пароль, «Сохранить»; запись попадает в открытую папку |
| Скопировать пароль из открытой карточки | 1 | 0 | |
| Предоставить доступ к записи другому отделу | 5 (вкладка «Доступ», «Предоставить доступ», поиск, выбор отдела, «Предоставить») | 1 | один компактный диалог, группа находится поиском по названию |

Найдено и исправлено в ходе прохода:

| Было | Проблема | Изменение | Стало |
| --- | --- | --- | --- |
| Первый вход руководителя нового отдела открывал пустую «Организацию» | Пространство «Организация» открывается по умолчанию, даже если сейфов в нём нет, а в пространстве отдела они есть: руководитель видел пустой экран без кнопки «Добавить запись» | Если в пространстве по умолчанию нет сейфов, открывается первое пространство, где они есть | сразу открыт отдел |
| Руководитель из мастера имел только роль через группу | Проверка «уже участник» засчитывала участие через группу, поэтому прямая роль администратора сейфа не выдавалась; у руководителя не было кнопки «Предоставить доступ» к записям | Проверка смотрит на прямую роль (`directRole`); тест проверяет её по API | руководитель — администратор сейфа напрямую и выдаёт доступ сам |

## Ограничения тестирования

- Создание отдела замерено полностью; остальные сценарии (папки, пароли, выдача доступа, перевод, увольнение, нагрузка) — следующие блоки аудита.
- Тестовый LDAP/AD, проверка установки на чистых ВМ (Ubuntu 22.04/24.04, Debian 12) и HTTPS на этом стенде не выполнялись; проверка установки есть в CI (задача `installer`).
- Время — автоматизированное, без «времени подумать».
