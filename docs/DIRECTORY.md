# Вход через каталог (LDAP / LDAPS / Active Directory)

Администратор: «Администрирование» → «Каталог (LDAP)».

## Несколько подключений

В разделе каталога можно выбрать, добавить, изменить и удалить подключение. Каждое имеет собственное название, адрес, TLS/CA, служебную запись, базовый DN, фильтр пользователей и привязки групп. На странице входа пользователь выбирает включённое подключение по его названию. Одинаковый DN в разных подключениях считается разными идентичностями; уже зарегистрированная учётная запись с совпадающей почтой не присоединяется к другому каталогу.

Ранее сохранённая настройка `ldap.config` автоматически читается как подключение `default`, без изменения DN пользователей или зашифрованного служебного пароля. При первом сохранении создаётся список `ldap.profiles`; прежний API `/admin/ldap` продолжает управлять подключением `default`. Новые подключения получают постоянный идентификатор. Секреты никогда не возвращаются через API; пустое поле пароля сохраняет текущий секрет, отдельный флажок удаляет его.

Подключение с зарегистрированными пользователями удалить нельзя: его можно отключить, сохранив связь с существующими данными. Отключение завершает сеансы пользователей этого подключения; проверка состояния подключения также действует для API-токенов и завершения MFA. Обратное включение не восстанавливает завершённые сеансы. Самостоятельно заблокированные пользователи не разблокируются синхронизацией.

## Как это работает

- Пароль каталога проверяет сам каталог (привязка от имени пользователя). Сервер Arklock его не сохраняет.
- **Пароль разблокировки сейфов остаётся отдельным.** Он шифрует данные в браузере и серверу неизвестен. При первом входе пользователь каталога придумывает пароль разблокировки сейфов, браузер создаёт ключи и ключ восстановления (как при обычной регистрации). При следующих входах: пароль каталога → экран разблокировки (пароль разблокировки сейфов).
- Учётные записи каталога **не входят по одному паролю разблокировки сейфов**: отключение в каталоге закрывает доступ (после синхронизации или при следующем входе).
- Если включён второй фактор, он требуется и при входе через каталог.
- Существующая локальная учётная запись с тем же адресом **не присоединяется** автоматически (ответ 409): чужой каталог не может захватить локальную запись.

## Настройка: три шага

Раздел «Администрирование → Интеграции → Active Directory / LDAPS». Вверху — состояние подключения по отдельности: «Подключение проверено», «Вход сотрудников включён / выключен», «Вход сотрудника проверен» и сводка дополнительных возможностей. Выключенная синхронизация или отсутствие сопоставленных групп — не ошибка подключения и так не показывается.

### 1. Подключение к каталогу

| Поле | Значение |
| --- | --- |
| Каталог | Active Directory (по умолчанию) или другой LDAP-каталог |
| Адрес сервера | `ldaps://dc01.example.com:636` (рекомендуется) или `ldap://…:389` со StartTLS. Пробелы, регистр схемы и `/` в конце исправляются сами; ошибка показывается под полем с примером |
| Служебная учётная запись и пароль | `CN=…` (полный DN), `svc-ldap@example.com` или `EXAMPLE\svc-ldap`; короткое имя дополняется доменом из Base DN. Пароль хранится зашифрованным и не возвращается |
| Base DN | можно оставить пустым: при проверке он определяется по каталогу (RootDSE, `defaultNamingContext`), и форма показывает найденное значение |
| Сертификат | файл `.cer`, `.crt` или `.pem` центра сертификации (PEM или DER). Если контроллер предъявляет самоподписанный сертификат или сертификат на другое имя, после проверки можно нажать **«Доверять этому сертификату»** — подключение будет принимать ровно его (по отпечатку SHA-256) |

StartTLS, передача паролей без шифрования и отключение проверки сертификата собраны в свёрнутом блоке «Особые случаи». **«Проверить подключение»** проверяет то, что в форме, до сохранения (этапы описаны ниже); **«Сохранить подключение»** сохраняет и сразу проверяет сохранённое — так появляется отметка «Подключение проверено».

### 2. Вход сотрудников

- **«Разрешить вход доменным учётным записям»** — включает вход через это подключение.
- **«Кто может входить»** — «все действующие учётные записи каталога» (найденные фильтром; отключённые в каталоге не входят) или «только участники выбранных групп» (в Active Directory учитываются вложенные группы). Для нового подключения выбор обязателен: доступ всем не открывается без решения администратора. Подключения, которые уже были включены до версии 1.87.0, продолжают работать как раньше («все найденные фильтром»), пока администратор не выберет иное. Группу можно найти по имени прямо на этом шаге.
- **«Создавать учётную запись Arklock при первом входе»** — при первом входе сотрудник сам задаёт пароль разблокировки сейфов, ключи создаются в его браузере; доменный пароль только подтверждает личность и не сохраняется.
- **«Проверить вход сотрудника»** — логин (`логин`, `DOMAIN\логин` или `логин@домен`) и пароль реального сотрудника. Каталог проверяет пароль; учётная запись в Arklock не создаётся, пароль не сохраняется и не попадает в журнал. Результат называет причину: вход работает; пароль верный, но учётная запись не входит в разрешённые группы; не найден (или отключён) в каталоге; неверный пароль (код 52e); заблокирована (775); локальная учётная запись с тем же адресом уже есть; создание при первом входе выключено и т. п. Успешная проверка отмечается как «Вход сотрудника проверен».

При входе сотрудника, не прошедшего правило «кто может входить», Arklock отвечает «вход для этой учётной записи не разрешён» (событие `auth.ldap.not_allowed`). Существенное изменение подключения (адрес, Base DN, учётная запись, фильтр, сертификат, правило входа) сбрасывает отметки «проверено».

### 3. Дополнительно (по необходимости)

Фильтр поиска пользователей (для Active Directory по умолчанию — только действующие учётные записи людей: `objectCategory=person`, без отключённых по `userAccountControl`), атрибуты почты, имени и карточки сотрудника, сопоставление групп каталога группам Arklock, плановая синхронизация, предпросмотр сверки, поиск и просмотр каталога. Просмотр по умолчанию показывает только действующих пользователей, по 50 записей с кнопкой «Показать ещё» (не дальше 500-й записи).

Предпросмотр и синхронизация доступны для сохранённого и включённого подключения; для выключенного они отвечают «вход через каталог выключен», для несохранённого — «сначала сохраните подключение».

Привязанные круги являются управляемыми каталогом: при входе и синхронизации членство пользователей соответствующего подключения сверяется с его группами. Для ручных назначений используйте отдельные круги. Удаление последней привязки к кругу удаляет из него пользователей этого подключения; участники других подключений и локальные пользователи сохраняются.

Плановая синхронизация запускается каждые **30 минут** (по умолчанию выключена). Учётная запись, отключённая в каталоге, теряет сеансы Arklock при ближайшей сверке. Недоступность каталога фиксируется как ошибка и не превращается в массовую блокировку пользователей.

Наличие записи в каталоге не создаёт готового пользователя с ключами на сервере: регистрация завершается только после успешного входа и создания ключей браузером.

## Права на хранилища

Членство в круге даёт пользователю роль круга в хранилищах, где круг подключён. Ключ хранилища новому участнику круга выдаёт администратор хранилища (как для любого участника: ключ подписывается выдающим); до этого хранилище отображается как «ожидает ключ».

## Единый вход (OpenID Connect)

«Администрирование» → «Единый вход (SSO)». Подходит любой провайдер OpenID Connect (Keycloak, Microsoft Entra ID, Okta, Google и др.).

1. В панели виден **адрес возврата** (`<APP_PUBLIC_URL>/api/v1/auth/sso/callback`) — зарегистрируйте его у провайдера. Без публичного адреса (Администрирование → Настройки → Сеть и доступ или `APP_PUBLIC_URL`) включить SSO нельзя.
2. Укажите издателя (issuer), идентификатор и секрет клиента (секрет хранится зашифрованным и не возвращается), при необходимости — допустимые домены почты.
3. Кнопка «Проверить провайдера» читает документ discovery, сверяет издателя и загружает ключи подписи.

Защита: код авторизации с PKCE (S256), одноразовое `state`, `nonce`; подпись id_token проверяется по ключам издателя (допускаются только RS256/RS384/RS512/ES256/ES384; `none` и HMAC отвергаются — защита от подмены алгоритма), проверяются издатель, аудитория, срок и `nonce`; непроверенная почта и почта вне разрешённых доменов отвергаются; провайдер без HTTPS допускается только по явному разрешению. Результат возвращается в приложение одноразовым билетом во фрагменте адреса (в журналы сервера он не попадает).

Как и для каталога: пароль разблокировки сейфов отдельный, существующая локальная запись с тем же адресом не захватывается, второй фактор и блокировка учётной записи действуют.

## Чего нет

SCIM и автоматическое следование за перемещёнными DN пока не реализованы. Для SAML используется отдельный раздел администрирования.

## Active Directory по LDAPS и сертификат центра сертификации

Раздел называется «Active Directory / LDAPS». Основной способ подключения — `ldaps://сервер:636` с проверкой сертификата сервера: цепочка до загруженного (или системного) центра, срок действия и **совпадение имени** сервера с сертификатом. Простое `ldap://` и отключение проверки сертификата оставлены только для изолированных стендов и для диагностики: их включает только главный администратор, с подтверждением паролем разблокировки сейфов и записью в журнал (`admin.ldap.insecure`); см. [подтверждение действий](security/admin-confirmation.md).

### Сертификат

Кнопка **«Загрузить сертификат»** принимает файлы `.cer`, `.crt` и `.pem` — как их выдаёт корпоративный центр сертификации: PEM (`-----BEGIN CERTIFICATE-----`), DER (двоичный) или base64 без заголовков. Конвертировать вручную не нужно. В одном файле может быть цепочка. После загрузки для каждого сертификата показываются имя, издатель, срок действия, отпечаток SHA-256, вид (корневой центр, промежуточный центр, сертификат сервера) и результат проверки цепочки: «до корневого центра проверена» или какой издатель не загружен. Отклоняются с понятной причиной: закрытые ключи и контейнеры `.pfx`/`.p12`, файлы, не являющиеся сертификатом X.509, наборы, в которых все сертификаты просрочены. Сертификат сервера (не центра) принимается, но помечается: для проверки нужен центр, которым он подписан. Сертификат хранится в профиле каталога в виде PEM; системное хранилище доверенных сертификатов сервера не меняется.

### Пошаговая проверка

**«Проверить подключение»** проверяет то, что сейчас в форме (сохранять не обязательно), и останавливается на первом неудачном этапе:

| Этап | Что проверяется | Пример причины |
| --- | --- | --- |
| Настройки | адрес, способ защиты, учётная запись | «После адреса и порта ничего не указывается: Base DN задаётся отдельным полем» |
| Имя сервера (DNS) | разрешение имени | «Имя не найдено в DNS» |
| Соединение | TCP до порта | «Порт закрыт», «нет ответа: проверьте маршрут и межсетевой экран» |
| TLS и сертификат | цепочка, срок, имя (сведения о сертификате сервера — в подробностях) | «Сертификат не подтверждён: загрузите корневой и промежуточный центры», «выдан на другое имя» |
| Вход служебной учётной записи | простой вход | коды Active Directory: `52e` — неверное имя или пароль, `525` — нет учётной записи, `775` — заблокирована, `533` — отключена, `532`/`773` — пароль истёк или должен быть сменён, `701` — истёк срок учётной записи |
| Base DN | чтение | «Base DN не найден», «нет прав на чтение» |
| Фильтр и пользователи | поиск по фильтру | «Фильтр не принят», «по фильтру никто не найден» |
| Группы из сопоставления | существование каждой группы | «Не найдено групп: N из M» |

Текст ответа сервера (например, `80090308: LdapErr: … data 52e …`) показывается в раскрывающемся блоке «Подробности». Пароли и ключи в результат и в журнал не попадают.

### Сохранение и пароль служебной записи

Ошибки в полях показываются **под полями** ещё до отправки; сервер проверяет те же правила повторно и в ответе указывает все неверные поля сразу. Пустое поле пароля при наличии сохранённого означает «оставить прежний» — пароль не теряется при правке других полей. При смене адреса сервера пароль нужно ввести заново: сохранённый пароль никогда не отправляется на другой сервер (ни при сохранении, ни при проверке). После успешного сохранения пометка «Есть несохранённые изменения» исчезает, а форма заново читает сохранённые значения.
