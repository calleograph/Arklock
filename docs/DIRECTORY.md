# Вход через каталог (LDAP / LDAPS / Active Directory)

Администратор: «Администрирование» → «Каталог (LDAP)».

## Несколько подключений

В разделе каталога можно выбрать, добавить, изменить и удалить подключение. Каждое имеет собственное название, адрес, TLS/CA, служебную запись, базовый DN, фильтр пользователей и привязки групп. На странице входа пользователь выбирает включённое подключение по его названию. Одинаковый DN в разных подключениях считается разными идентичностями; уже зарегистрированная учётная запись с совпадающей почтой не присоединяется к другому каталогу.

Ранее сохранённая настройка `ldap.config` автоматически читается как подключение `default`, без изменения DN пользователей или зашифрованного служебного пароля. При первом сохранении создаётся список `ldap.profiles`; прежний API `/admin/ldap` продолжает управлять подключением `default`. Новые подключения получают постоянный идентификатор. Секреты никогда не возвращаются через API; пустое поле пароля сохраняет текущий секрет, отдельный флажок удаляет его.

Подключение с зарегистрированными пользователями удалить нельзя: его можно отключить, сохранив связь с существующими данными. Отключение завершает сеансы пользователей этого подключения; проверка состояния подключения также действует для API-токенов и завершения MFA. Обратное включение не восстанавливает завершённые сеансы. Самостоятельно заблокированные пользователи не разблокируются синхронизацией.

## Как это работает

- Пароль каталога проверяет сам каталог (привязка от имени пользователя). Сервер Arklock его не сохраняет.
- **Мастер-пароль остаётся отдельным.** Он шифрует данные в браузере и серверу неизвестен. При первом входе пользователь каталога придумывает мастер-пароль, браузер создаёт ключи и ключ восстановления (как при обычной регистрации). При следующих входах: пароль каталога → экран разблокировки (мастер-пароль).
- Учётные записи каталога **не входят по одному мастер-паролю**: отключение в каталоге закрывает доступ (после синхронизации или при следующем входе).
- Если включён второй фактор, он требуется и при входе через каталог.
- Существующая локальная учётная запись с тем же адресом **не присоединяется** автоматически (ответ 409): чужой каталог не может захватить локальную запись.

## Настройка

| Поле              | Значение                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------- |
| Адрес             | `ldaps://host:636` (рекомендуется) или `ldap://host:389` со StartTLS                                          |
| Сертификат CA     | PEM корневого/промежуточного сертификата, если каталог использует внутренний центр сертификации               |
| Служебная запись  | DN и пароль для поиска пользователей (пароль хранится зашифрованным ключом из секрета приложения и не возвращается API) |
| Базовый DN        | где искать пользователей                                                                                      |
| Фильтр            | по умолчанию `(&(objectClass=person)(\|(uid={u})(mail={u})(sAMAccountName={u})(userPrincipalName={u})))`; `{u}` экранируется (RFC 4515) |
| Атрибуты          | почта (`mail`) и имя (`cn`)                                                                                   |
| Группы → круги    | члены группы каталога автоматически состоят в круге Arklock (при входе и при синхронизации)                   |

`ldap://` без StartTLS отвергается, если администратор явно не разрешил передачу паролей без шифрования («только изолированная сеть»).

Кнопки: **Проверить соединение** (подключение, служебная привязка, чтение базы), **Найти пользователя** (DN, почта, имя, группы — без паролей), **Синхронизировать** (блокирует учётные записи, исчезнувшие из каталога или отключённые в нём — бит `ACCOUNTDISABLE` в `userAccountControl`, — завершает их сеансы и обновляет круги). **Предпросмотр сверки** показывает, что сделает синхронизация, ничего не меняя: кого отключат и почему, у кого изменятся круги и поля карточки, кто есть в каталоге, но ещё не входил (до 500 записей обзора), и пример полученных данных.

Все эти действия относятся к выбранному подключению и используют его **сохранённые** настройки. Просмотр каталога показывает пользователей, группы и подразделения OU; можно фильтровать по имени/почте и DN подразделения в пределах базового DN. Результат ограничен 100 записями: для больших каталогов уточняйте фильтр или OU. Группу из результатов можно добавить в привязки и выбрать круг Arklock; затем сохраните настройку. Кнопка использования OU как базового DN меняет фильтр области поиска пользователей после сохранения.

Привязанные круги являются управляемыми каталогом: при входе и синхронизации членство пользователей соответствующего подключения сверяется с его LDAP-группами. Для ручных назначений используйте отдельные круги. Удаление последней привязки к кругу удаляет из него пользователей этого подключения; участники других подключений и локальные пользователи сохраняются.

В каждом подключении можно включить плановую синхронизацию — она запускается каждые **30 минут** (отдельно от обслуживания сервера; следующий запуск не начинается, пока не завершён предыдущий). Учётная запись, отключённая в каталоге, теряет сеансы Arklock при ближайшей сверке. По умолчанию синхронизация отключена. Панель показывает время последнего запуска, число проверенных/обновлённых/заблокированных пользователей и ошибки. Ручная синхронизация доступна сразу. Недоступность каталога фиксируется как ошибка и не превращается в массовую блокировку пользователей. Смена DN/повторное назначение той же почты другой LDAP-записи не переносит доступ автоматически.

Наличие записи в каталоге или результат просмотра не создаёт готового пользователя с ключами на сервере. Регистрация завершается только после успешного LDAP-входа и создания ключей браузером; до завершения дополнительно проверяются состояние подключения, доступность и актуальность идентичности в каталоге. Пользователю каталога, которого отключили в AD, отказывают во входе и завершают уже действующие сеансы при следующей проверке входа либо синхронизации.

## Права на хранилища

Членство в круге даёт пользователю роль круга в хранилищах, где круг подключён. Ключ хранилища новому участнику круга выдаёт администратор хранилища (как для любого участника: ключ подписывается выдающим); до этого хранилище отображается как «ожидает ключ».

## Единый вход (OpenID Connect)

«Администрирование» → «Единый вход (SSO)». Подходит любой провайдер OpenID Connect (Keycloak, Microsoft Entra ID, Okta, Google и др.).

1. В панели виден **адрес возврата** (`<APP_PUBLIC_URL>/api/v1/auth/sso/callback`) — зарегистрируйте его у провайдера. Без публичного адреса (Администрирование → Настройки → Сеть и доступ или `APP_PUBLIC_URL`) включить SSO нельзя.
2. Укажите издателя (issuer), идентификатор и секрет клиента (секрет хранится зашифрованным и не возвращается), при необходимости — допустимые домены почты.
3. Кнопка «Проверить провайдера» читает документ discovery, сверяет издателя и загружает ключи подписи.

Защита: код авторизации с PKCE (S256), одноразовое `state`, `nonce`; подпись id_token проверяется по ключам издателя (допускаются только RS256/RS384/RS512/ES256/ES384; `none` и HMAC отвергаются — защита от подмены алгоритма), проверяются издатель, аудитория, срок и `nonce`; непроверенная почта и почта вне разрешённых доменов отвергаются; провайдер без HTTPS допускается только по явному разрешению. Результат возвращается в приложение одноразовым билетом во фрагменте адреса (в журналы сервера он не попадает).

Как и для каталога: мастер-пароль отдельный, существующая локальная запись с тем же адресом не захватывается, второй фактор и блокировка учётной записи действуют.

## Чего нет

SCIM и автоматическое следование за перемещёнными DN пока не реализованы. Для SAML используется отдельный раздел администрирования.
