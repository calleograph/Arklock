# Резервное копирование и восстановление

Статус проверки: создание, проверка, отказ при повреждении и восстановление после полного уничтожения БД проверяются в CI (задача `installer`). Восстановление на **другом** чистом сервере, расписание, S3/SMB и раздел веб-панели **не реализованы / не проверены**.

## Что входит в копию

Один зашифрованный файл `*.bak.gpg` (GnuPG, AES-256, парольная фраза из `BACKUP_KEY_FILE`) с:

- дампом PostgreSQL: учётные записи, зашифрованные клиентом записи, зашифрованные закрытые ключи пользователей, настройки, журнал;
- файлом конфигурации `arklock.env`;
- манифестом (версия, число миграций, контрольная сумма дампа). Рядом лежит `*.bak.gpg.json` с контрольной суммой файла (без секретов).

**Для менеджера паролей это главное:** пользователи шифруют данные мастер-паролями на клиенте; ключи пользователей находятся в самой БД. Поэтому дамп восстанавливает доступ ко всем секретам — пользователи входят прежними мастер-паролями. Это проверяется в CI: после уничтожения БД и восстановления тот же пользователь расшифровывает ту же запись.

## Ключ резервного шифрования

Создаётся установщиком: `/etc/arklock/backup.key` (права 600). Он **хранится отдельно от копий** и не входит в каталог данных. **Скопируйте его в надёжное место вне сервера** — без него копии не расшифровать.

## Команды

```bash
sudo scripts/backup.sh [--keep 14] [--label имя]     # создать копию (проверяется сразу после создания)
sudo scripts/backup.sh --verify ФАЙЛ                 # проверить существующую копию (расшифровка, контрольная сумма, читаемость дампа)
sudo scripts/restore.sh ФАЙЛ [--yes]                 # восстановить (работает без веб-приложения)
```

Восстановление: проверяет копию, сверяет версию миграций (копия новее установленного приложения — отказ), требует подтверждение, создаёт **аварийную копию** текущего состояния (метка `pre-restore`), пересоздаёт БД, загружает данные, запускает приложение. Файл `arklock.env` текущего сервера не заменяется.

### Перенос на новый сервер

1. `install.sh` на новом сервере (тот же профиль).
2. Скопировать ключ резервного шифрования в `/etc/arklock/backup.key` (права 600) и файл копии в `DATA_ROOT/backups`.
3. `sudo scripts/restore.sh ФАЙЛ`.

## Ротация и место

`--keep N` оставляет N последних копий проекта (по умолчанию 14). Перед созданием проверяется свободное место.
