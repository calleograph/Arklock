# Обновление через веб-интерфейс (проект)

Состояние: **проект, не реализовано** (Этап 5). Документ фиксирует границы безопасности, чтобы остальные части системы проектировались с их учётом.

## Принцип
Веб-приложение **не имеет доступа** к Docker-сокету, git и оболочке хоста. Оно только кладёт запрос в каталог обмена; действия выполняет отдельный **update-agent** на хосте (systemd-служба с минимальными привилегиями), который понимает фиксированный набор операций.

```
Админ в браузере ─▶ API (проверка прав + повторная проверка личности/MFA) ─▶ запись request в каталог обмена
                                                                                   │
        update-agent (хост) ◀── читает, строго валидирует, выполняет белый список ◀┘
              │  check → GitHub Releases API (только заданный репозиторий)
              │  update → pull образа ПО DIGEST из GHCR → backup БД → миграции → healthcheck → итог
              └─ status.json / update.log ─▶ API читает и показывает в «Система → Обновления»
```

## Операции agent (исчерпывающий список)
`check`, `update <версия из check>`, `rollback`, `status`. Параметры — простые строки `key=value`, каждое значение проверяется по шаблону. Произвольные команды, пути и образы запрещены; источник образа жёстко задан в конфигурации agent (`ghcr.io/calleograph/arklock`), выбор другого невозможен из интерфейса.

## Инварианты
- Одновременно один процесс обновления (файловая блокировка).
- Перед обновлением: резервная копия БД и сохранение предыдущего тега/digest образа.
- Проверка digest образа (и подписи — после включения подписи релизов); при несовпадении обновление не начинается.
- Миграции помечаются как обратимые/необратимые; при необратимой миграции интерфейс явно предупреждает, что откат = восстановление из копии.
- Итог из четырёх независимых статусов: Update / Deployment / Health / Integrations.
- Дочерние команды запускаются в стерильном окружении (`env -i`).
- Все действия пишутся в Ledger (кто, когда, откуда версия → куда).
- Закрытый контур: режим «локальный registry» и «офлайн-пакет» (образы + манифест), внешние проверки отключаются настройкой.
