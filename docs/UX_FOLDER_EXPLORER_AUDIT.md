# UX-аудит: проводник сейфа в центральной области (1.81.0)

Что проверялось: работа с папками и записями в рабочем пространстве. До 1.81.0 папки были только в левом дереве, центр показывал плоский список записей выбранной папки вместе со всеми вложенными. Начиная с 1.81.0 центр — проводник текущего места: путь, раздел «Папки», записи.

## Как считалось

Числа ниже — **число действий пользователя** (нажатие или ввод), посчитанное по коду прежней версии и по сценарию браузерного теста `e2e/unified-ui.spec.ts` («проводник сейфа…») новой. Время и ошибки живых людей не измерялись: пользовательских испытаний не проводилось. Поэтому «понимание пути» оценивается по признакам (виден ли путь, можно ли по нему перейти), а не по секундам.

## Было / Стало

| Сценарий | Было | Стало |
| --- | --- | --- |
| Создать подпапку в открытой папке | выбрать папку в дереве, нажать значок «+» над деревом (без текстовой подписи), ввести название, «Сохранить» — 4 действия; либо «⋯» у папки → «Создать подпапку» → название → «Сохранить» — 4 | «Создать папку» (подписанная кнопка в разделе «Папки») → название → «Сохранить» — 3 действия, папка открыта уже |
| Спуститься на три уровня вниз | 3 нажатия по дереву, плюс по одному на раскрытие свёрнутой ветки (до 6) | 3 нажатия по папкам в центре; дерево раскрывается само |
| Вернуться на уровень выше | найти родителя в дереве, 1 нажатие | кнопка «На уровень выше» или сегмент пути, 1 нажатие; «Назад» браузера тоже работает |
| Вернуться на три уровня | найти предка в дереве, 1 нажатие | 1 нажатие по сегменту пути (длинный путь свёрнут в «…», остаётся 1–2 нажатия) |
| Создать запись в нужной папке | выбрать папку, «Добавить запись» — 2 | то же, 2: форма подставляет открытую папку |
| Перенести запись в другую папку | выделить, выбрать папку в списке массовой панели, «Перенести» — 3; либо перетащить на дерево | те же способы; плюс перетаскивание на папку в центре |
| Понять, где находишься | выделение в дереве; путь виден только у записи в строке | путь над содержимым; текущая папка выделена и в дереве; адрес содержит папку |
| F5 | возврат в «Все записи», выбранная папка терялась | открытая папка, дерево и путь сохраняются |

Вывод: число действий при создании подпапки почти не изменилось (4 → 3), потому что дерево и раньше позволяло создать её внутри выбранной папки. Выигрыш в другом: действие подписано и находится в самом месте, где пользователь смотрит на содержимое; спуск по уровням не требует раскрывать дерево; путь можно нажимать; F5 и «Назад» не теряют место.

## Найденные неудобства и что с ними сделано

- Раздел папок без записей занимал бы много места на ноутбуке: строки компактные (одна строка высотой около 32 пикселей, колонки подстраиваются под ширину), больше 12 папок сворачиваются под «Показать все (N)».
- Поиск внутри папки раньше искал во вложенных папках, а список без поиска тоже показывал все вложенные записи, из-за чего родительская папка выглядела «набитой». Теперь без поиска и фильтров показываются записи самой папки, а поиск и фильтры ищут вглубь, и папки в центре в этот момент скрыты. Режимы просмотра папки, поиска, избранного, архива и корзины не смешиваются.
- «Избранное», «Архив» и «Корзина» раньше оставляли внутри выбранную папку, которая оживала при возврате. Теперь переход в них сбрасывает папку: состояние навигации одно.
- Удаление папки, которая сейчас открыта, возвращает в родительскую, а не на корень.
- Идентификаторы тестов центра отделены от дерева (`tile-*`), иначе существующие сценарии находили бы две папки с одним тестовым идентификатором.

## Права и изоляция

Центр строится из того же списка папок, который сервер отдаёт сотруднику для дерева. Сервер не присылает недоступные папки, их названия и записи (`apps/api/test/explorer-visibility.test.ts`, `structure.test.ts`, `object-access.test.ts`). Папка, родитель которой недоступен, показывается на верхнем уровне и в пути начинается с неё. Прямые обращения к скрытым записям и доступу скрытой папки дают «не найдено». Идентификатор в адресе (`?folder=`) учитывается только если эта папка есть в дереве сотрудника. Главный администратор не получает дополнительных возможностей просмотра: проводник читает те же расшифрованные данные.

## Производительность

- Новых запросов к серверу нет: проводник использует дерево, которое загружается один раз на сейф.
- Построение индекса папок и пути — `apps/web/test/explorer.test.ts`: 600 папок и пять уровней обрабатываются в среднем быстрее 20 мс на цикл (тест с запасом; реальные значения заметно меньше).
- Создание, перемещение и удаление папок перезагружают дерево, как и раньше; другие данные не перечитываются.
- Не проверено: тысячи записей в одной папке в реальном браузере. Список записей не виртуализирован, на таком объёме прокрутка тяжелее. Нагрузочные прогоны не запускались.

## Адаптивность и темы

Сценарий `ui` проверяет отсутствие горизонтальной прокрутки на 1280×800, 1366×768, 1440×900, 1512×982, 1920×1080 и 390×844, и показ пути во всех десяти темах. Снимки: `docs/screenshots/ui-explorer-1366.png`, `docs/screenshots/ui-explorer-390.png`. На ширине до 1024 пикселей проводник находится на вкладке «Записи», левое дерево — на вкладке «Папки».

## Что не сделано

- Перемещение папок перетаскиванием (есть через меню).
- Виртуализация списка записей.
- Фильтр по названию внутри очень большого списка папок (сейчас — «Показать все» и дерево слева).
- Сквозная проверка прав в браузере двумя сотрудниками с общим сейфом: права проверены на уровне API-тестов и по структуре данных, браузерный сценарий проверяет только то, что чужой сотрудник по прямой ссылке ничего не получает.
