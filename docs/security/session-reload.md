# Разблокировка после обновления страницы (F5)

Ключи сотрудника живут в памяти вкладки. Раньше обновление страницы стирало их, и Arklock снова просил мастер-пароль. Теперь при действующем сеансе F5 не требует пароля.

## Как это устроено

1. При разблокировке браузер запрашивает у сервера случайную долю (32 байта) для текущего сеанса. Сервер хранит её запечатанной ключом приложения в строке сеанса. Доля одна на сеанс, вкладки одного сеанса её разделяют.
2. Из доли через HKDF браузер получает ключ и шифрует им свои закрытые ключи (AES-256-GCM, привязка к пользователю). Шифртекст хранится только в `sessionStorage` этой вкладки.
3. После F5 вкладка по действующему токену получает долю, открывает ключи и продолжает работу.

Мастер-пароль, ключ обёртки и открытые закрытые ключи нигде не сохраняются. Сервер не может расшифровать ключи без шифртекста вкладки, вкладка не может без действующего сеанса.

## Когда снова нужен мастер-пароль

| Событие | Что происходит |
| --- | --- |
| F5, Ctrl+F5, «Назад» и «Вперёд» | Ключи открываются долей сеанса, пароль не нужен. |
| Новая вкладка того же браузера | Получает токен и шифртекст от уже открытой вкладки (`BroadcastChannel`, только тот же источник), пароль не нужен. |
| Кнопка «Заблокировать» | Доля на сервере стирается, все вкладки сеанса блокируются. Нужен мастер-пароль или PIN. |
| Автоблокировка по бездействию | Блокируется простаивающая вкладка, её шифртекст стирается; соседняя вкладка, где идёт работа, не блокируется. |
| Выход, отзыв сеанса, блокировка сотрудника, смена пароля в другом сеансе, истечение сеанса | Сервер не выдаёт долю; нужен полный вход. |
| Закрытие вкладки, перезапуск браузера | `sessionStorage` вкладки исчезает; нужен вход (или PIN на доверенном устройстве). |
| Обновление Arklock, перезапуск сервера | Сеансы хранятся в базе, доля переживает перезапуск; F5 работает. |

Администратор может выключить механизм: Администрирование → Настройки → Безопасность → «Не запрашивать мастер-пароль после обновления страницы». После выключения сервер перестаёт выдавать доли.

## Границы

Тот, кто управляет кодом страницы (XSS) или получил доступ к профилю браузера с открытой вкладкой и действующим сеансом, может открыть ключи. Это тот же уровень, что и у разблокированной вкладки, ключи которой и так в памяти. Независимой проверки схемы не проводилось.
