# Дорожная карта и критерии приёмки

Критерий считается выполненным, только если он подтверждён автоматической проверкой в CI или явно указанным ручным прогоном. Статус: ✅ выполнено и подтверждено, 🔶 частично, ⬜ не начато.

## Этап A. Релизный конвейер и установка одной командой

| №   | Критерий приёмки                                                                                                                                           | Статус |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| A1  | Публичный репозиторий; анонимный `curl https://raw.githubusercontent.com/calleograph/arklock/main/README.md` возвращает 200                                 | ⬜     |
| A2  | Тег `vX.Y.Z` запускает workflow: образ `ghcr.io/calleograph/arklock:X.Y.Z` (linux/amd64, linux/arm64) публикуется, digest записывается в `release.json`     | ⬜     |
| A3  | GitHub Release содержит `install.sh`, `release.json`, `SHA256SUMS`; описание — раздел версии из `CHANGELOG.md`                                                | ⬜     |
| A4  | Анонимный `docker pull ghcr.io/calleograph/arklock@<digest>` успешен                                                                                       | ⬜     |
| A5  | На чистом раннере Ubuntu 24.04: скачивание `install.sh` из Release, проверка `SHA256SUMS`, установка с получением образа по digest (без сборки на сервере)   | ⬜     |
| A6  | Та же установка на чистом Debian 12 (контейнер с systemd или ВМ) завершается успешно и проходит `verify.sh`                                                 | ⬜     |

## Этап B. Помощник обновлений и обновление через браузер

| №   | Критерий приёмки                                                                                                                                                                                | Статус |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| B1  | `scripts/updater.sh install/status/repair/uninstall/run`; служба systemd переживает перезапуск; веб-приложение не имеет Docker-сокета и не исполняет команды                                      | ✅ |
| B2  | Помощник принимает только запросы из белого списка (`check`, `update`, `rollback`, `backup`, `verify`); тесты: неизвестное действие, неверная версия, подложенная ссылка, параллельный запрос отвергаются | ✅ |
| B3  | Страница «Обновления и версии» показывает: установленную версию, commit, дату сборки, доступную версию, время проверки, состояние помощника, изменения из CHANGELOG, историю                        | ✅ |
| B4  | Кнопки «Проверить», «Обновить», «Откатить» доступны только администратору с повторным подтверждением мастер-пароля (≤ 5 минут)                                                                    | ✅ |
| B5  | Браузерный тест (Playwright) в CI: вход администратором → «Проверить» → «Обновить» до тестового релиза → прогресс по этапам → новая версия в интерфейсе, данные на месте                           | ✅ |
| B6  | Браузерный тест: обновление со сбойной миграцией завершается восстановлением; интерфейс показывает причину и прежнюю версию                                                                       | ✅ |
| B7  | Образ берётся по digest из `release.json`; несовпадение digest останавливает обновление до остановки сервисов (тест)                                                                               | ⬜     |

## Этап C. Административная панель

| №   | Критерий приёмки                                                                                                                                                  | Статус |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| C1  | «Обзор»: версия, время работы, состояние БД/API/помощника, число пользователей, хранилищ, записей, активных сеансов, последнее обновление и копия                  | 🔶     |
| C2  | «Ресурсы»: CPU, память, разделы с занятым/свободным, размер БД, копий, журналов; предупреждение при свободном месте < 10 % или < 2 ГиБ (юнит-тест порогов)         | 🔶     |
| C3  | «Контейнеры»: только контейнеры проекта — имя, образ, статус, healthcheck, время работы; чужие контейнеры в ответе отсутствуют (тест рядом с чужим контейнером)     | 🔶     |
| C4  | «Журналы»: аудит и безопасность с фильтрами (время, пользователь, категория, результат), поиск, постраничность, экспорт CSV; секретов в записях нет (тест)         | 🔶     |
| C5  | «Резервное копирование»: список, создание, проверка, удаление, скачивание, расписание (время, число копий); выполнение по расписанию подтверждено тестом          | 🔶     |
| C6  | «Диагностика»: таблица проверок «Успешно/Предупреждение/Ошибка» с описанием, причиной и рекомендацией; диагностический пакет без секретов (тест)                    | 🔶     |
| C7  | LDAP/LDAPS: подключения, загрузка CA, проверка соединения, поиск тестового пользователя; bind-пароль хранится зашифрованным и не возвращается API (тесты)         | 🔶     |
| C8  | Сертификаты: цепочка, сроки, предупреждение за 30 дней; SMTP: проверка соединения и тестовое письмо (против локального SMTP-приёмника в CI)                        | 🔶     |
| C9  | Хранилища: категории (БД, вложения, копии, журналы, временные файлы) с объёмом и статусом; сверка метаданных и файлов без автоудаления                              | 🔶     |
| C10 | Каждая кнопка панели имеет рабочий backend и проверку роли; запрос без роли администратора → 403 (параметризованный тест по всем маршрутам `/api/v1/admin/*`)       | 🔶     |

## Этап D. Менеджер паролей (Этапы 3–4)

| №   | Критерий приёмки                                                                                                                                  | Статус |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| D1  | Argon2id в Web Worker: интерфейс не блокируется (замер: самая длинная задача главного потока при входе < 100 мс)                                    | 🔶     |
| D2  | Папки (вложенность, перемещение, защита от циклов), типы записей, теги, избранное, ревизии с восстановлением, корзина со сроком хранения            | ✅     |
| D3  | Вложения: шифрование на клиенте, потоковая передача, проверка целостности, тест обрыва передачи и повреждения                                      | 🔶     |
| D4  | Импорт/экспорт CSV и JSON Arklock; зашифрованный экспорт; предпросмотр; отчёт без секретов                                                          | ✅     |
| D5  | Общие хранилища, круги, роли, гранты, отзыв доступа с ротацией ключа; аутентифицированная передача ключей и сверка отпечатков                       | ✅     |
| D6  | MFA (TOTP, WebAuthn, резервные коды), LDAP/AD-вход, журнал безопасности с экспортом в syslog                                                        | 🔶     |

## Этап E. Готовность к тестированию пользователями

| №   | Критерий приёмки                                                                                                                              | Статус |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| E1  | Все критерии этапов A–C выполнены; README и документация соответствуют фактическому поведению                                                  | ⬜     |
| E2  | Восстановление на другом чистом сервере из копии подтверждено автоматическим прогоном                                                          | ⬜     |
| E3  | Прерывание обновления (kill в середине), нехватка места, недоступность БД и GitHub — отдельные автоматические сценарии                          | ⬜     |
| E4  | Независимая проверка криптографии выполнена и опубликована до рекомендации для реальных секретов                                                | ⬜     |

Этап B подтверждён в CI (задача `update-from-web` на раннере Ubuntu 24.04): служба помощника, отказ на подделанные запросы и ссылки, перезапуск службы, проверка и обновление из браузера с повторным вводом пароля, ход по этапам, данные на месте после обновления, релиз со сбойной миграцией восстанавливается и интерфейс показывает причину. Критерий B7 (образ по digest) зависит от публикации образов (Этап A).

Уже выполнено и подтверждено в CI: установка (standalone, shared-host), идемпотентность, шифрованное резервное копирование и восстановление после уничтожения БД, обновление и откат из командной строки, автовосстановление после сбоев миграции и сборки, учётные записи и личный сейф с клиентским шифрованием.

Примечания к этапу D: D1 — Argon2id вынесен в Web Worker и проверен сценариями входа; замер длинных задач главного потока не автоматизирован. D3 — передача файла выполняется одним запросом на стороне клиента (шифрование кусками), сервер принимает поток с точным контролем размера; потоковая обработка на стороне браузера (без загрузки файла целиком в память) и тест обрыва передачи в браузере не сделаны. D5 — подтверждено тестами API и сценарием в браузере (подписанные ключи, журнал ключей, отзыв и ротация).

D6: готовы TOTP и резервные коды; WebAuthn, LDAP/AD, экспорт в syslog — впереди.

Этап C: C1, C2, C3, C5, C6, C9, C10 реализованы и проверены автотестами (API, браузер); 🔶 означает, что проверка настоящего помощника на Ubuntu 24.04 запускается в CI (tests/updater/test-ops.sh) и фиксируется после зелёного прогона. C4 — аудит с фильтрами и CSV есть, системные журналы читаются через помощника. C7 (LDAP): подключение, проверка, поиск пользователя, шифрование bind-пароля и вход проверены на тестовом каталоге; проверка на настоящем OpenLDAP/AD и загрузка CA на живом сервере не выполнялись. C8 — сертификаты (публичный адрес и SMTP) и тестовое письмо готовы; проверка по произвольным узлам намеренно не реализована.
