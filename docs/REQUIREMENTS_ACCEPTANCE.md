# Матрица приёмки требований (версия 1.75.0)

Документ сводит ранее поставленные задачи с фактическим состоянием кода и проверок. Он не заменяет [состояние функций](FEATURE_STATUS.md): там подробности и границы каждой функции, здесь — ответ на вопрос «сделано ли то, что просили». Если две таблицы расходятся, верна та, где указан тест; расхождение — ошибка документации, о ней нужно сообщить.

**Статусы:** Готово — есть код и проверка в браузере или тест API; Частично — работает, но не весь сценарий (граница указана); Не реализовано; Не проверено — код есть, подтверждения в доступной среде нет; Неприменимо — следует из модели шифрования.

**Как читать колонки.** «Версия» — по [CHANGELOG](../CHANGELOG.md); для функций, появившихся задолго до 1.67, указан только раздел. «Проверка» — тесты API (`apps/api/test/*.test.ts`) и сценарии в настоящем браузере Chromium (`e2e/*.spec.ts`, Playwright). «Просмотр в браузере» всюду означает: страница открыта автоматически и снимки просмотрены мной на ширинах 1280, 1366, 390 и других (`docs/screenshots/`, [UX_FULL_AUDIT](UX_FULL_AUDIT.md), [UX_ENTERPRISE_JOURNEY_AUDIT](UX_ENTERPRISE_JOURNEY_AUDIT.md)); это не опрос людей и не проверка чтецом экрана.

**Решение по нескольким хранилищам.** Профили копий хранятся на сервере в файлах хост-помощника, который работает от имени администратора сервера и исполняет `scripts/updater.sh`; секреты лежат в файле с правами 600. Несколько профилей требуют переработки именно этой части: формат файла, расписание, порядок отправки, проверка каждого профиля и очистка. Она выполняется с правами хоста, а чистого сервера для проверки нет, поэтому изменение вслепую не делалось. Для вложений нужен слой `BlobStore` с выбором хранилища по сейфу, перенос файлов и проверка целостности каждого переноса. Оба изменения — отдельный архитектурный этап; независимые пункты продолжены.

## 9. Функциональная ревизия эталонного менеджера

Ревизия закрыта по всем пунктам, которые применимы к модели Arklock. Рабочие таблицы ревизии ведутся во внутренних заметках и в этот репозиторий намеренно не включены. Результат по классам:

- **Реализовано:** контекстные меню (копирование, избранное, копия, архив, корзина), значки и цвета, дополнительные поля, история объектов, уровни прав включая «Структуру», массовые операции над пользователями и записями, настройки генератора организации, правила автоматизации, срок учётной записи, еженедельный отчёт о здоровье паролей.
- **Не реализовано сознательно:** вход по JWT доверенного поставщика (токены API не расшифровывают данные, ценность низкая), группы под управлением самих сотрудников (требуют модели делегирования прав на выдачу ключей), сброс пароля по почте (ключи шифруются у пользователя, почта их не восстановит).
- **Частично:** отчёт о здоровье паролей приходит в колокольчик, но не по почте; правила автоматизации не умеют условий над расшифрованным содержимым (сервер его не видит).
- **Неприменимо:** шифрование «на стороне сервера» для стандартных пространств, нативные мобильные приложения, коммерческие ограничения тарифов.

Публичные документы названий исследованных продуктов не содержат; названия форматов импорта (KeePass, Passwork, Bitwarden) указаны только там, где они нужны для совместимости. Проверка — `scripts/check-private-data.mjs` перед каждой отправкой.
