# Вебхуки

Администрирование → Интеграции → Вебхуки. Вебхук отправляет во внешнюю систему (SIEM, чат, автоматизация) подписанное JSON-сообщение о событии журнала.

## Что отправляется

```json
{ "id": "…", "type": "admin.user.offboard", "at": "2026-10-18T09:00:00.000Z", "actor": "user:<id>", "target": "user:<id>", "detail": { "vaults": 2 } }
```

Это те же несекретные метаданные, что попадают в журнал и syslog: идентификаторы и коды. Пароли, записи, ключи и пароли разблокировки сейфов в сообщения не попадают, серверного токена с доступом к открытым секретам нет и быть не может: сервер их не знает.

## Подпись

Заголовки: `X-Arklock-Event`, `X-Arklock-Timestamp` (секунды), `X-Arklock-Signature: sha256=<hex>`, где подпись — `HMAC-SHA256(секрет, "<метка>.<тело>")`. Получатель обязан сверить подпись и отбросить сообщения со старой меткой. Секрет выпускается при создании (или по запросу «Выпустить новый секрет») и показывается один раз; в базе хранится только запечатанное значение.

## Защита и надёжность

- Только HTTPS; адреса во внутренних сетях, loopback и link-local запрещены, перенаправления не выполняются (защита от SSRF).
- Доставка в фоне, три попытки (сразу, через 1 и 5 секунд). Сбой не влияет на работу приложения; счётчики и последняя ошибка видны в панели.
- Очереди на диске нет: если Arklock перезапущен во время повторов, событие не будет доставлено повторно. Для строгого учёта используйте syslog или журнал.
- Фильтр по началу названия события (`auth.`, `admin.`); пусто — все события. До десяти вебхуков.
