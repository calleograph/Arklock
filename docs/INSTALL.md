# Установка

Статус проверки: установка, повторный запуск, профиль shared-host, зашифрованное резервное копирование и восстановление автоматически проверяются в CI на чистом раннере Ubuntu 24.04 (см. `.github/workflows/ci.yml`, задачи `installer` и `shared-host`). **Debian 12 и реальный сервер с перезагрузкой пока не проверялись.**

## Требования

- Ubuntu 24.04 LTS или Debian 12, архитектура x86_64 или aarch64, root-доступ.
- От 1 ГБ оперативной памяти, от 3 ГиБ свободного места в каталоге данных.
- Доступ в интернет (пакеты, Docker, репозиторий). Для закрытого контура — см. раздел «Ограничения».

## Установка одной командой

Одна команда (последний релиз):

```bash
curl -fsSL https://github.com/calleograph/arklock/releases/latest/download/install.sh | sudo bash
```

Если сначала хотите прочитать и проверить установщик:

```bash
curl -fsSLO https://github.com/calleograph/arklock/releases/latest/download/install.sh
curl -fsSLO https://github.com/calleograph/arklock/releases/latest/download/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS      # контрольная сумма install.sh
less install.sh                               # просмотрите, что будет выполнено
sudo bash install.sh                          # либо: sudo bash install.sh --ref vX.Y.Z
```

Установщик не исполняет содержимое ветки `main`: по умолчанию берётся последний релизный тег, а установка непомеченной ветки требует явного `--allow-unreleased`. Код релиза загружается из репозитория, готовый образ — из GHCR (`ghcr.io/calleograph/arklock:<версия>`), если его метка коммита совпадает с загруженным кодом; иначе образ собирается на сервере. Отключить загрузку образа: `ARKLOCK_PULL_RELEASE_IMAGE=0`.

## Что делает установщик

1. Проверяет ОС, архитектуру, память, место, права.
2. Определяет профиль: **standalone** (отдельный сервер) или **shared-host** (на сервере уже работают другие приложения). Выбор можно задать `--profile`.
3. Устанавливает недостающие пакеты и Docker Engine с Compose Plugin — только в профиле standalone.
4. Подбирает свободный порт на `127.0.0.1` (8080 и выше), создаёт каталоги, файл конфигурации `/etc/arklock/arklock.env` (права 600) со случайными секретами и ключ резервного шифрования `/etc/arklock/backup.key`.
5. Собирает образ, запускает PostgreSQL и приложение отдельным compose-проектом, применяет миграции.
6. Устанавливает помощника обновлений (служба systemd), выполняет `scripts/verify.sh` и печатает адрес и **одноразовый код настройки** для создания первого администратора.

Повторный запуск безопасен: секреты, тома и данные не пересоздаются.

### Профиль shared-host

Установщик **не устанавливает** Docker и пакеты, не меняет Nginx, чужие контейнеры, чужие порты и настройки системы. Занятый порт не занимается (`--port` на занятый порт — отказ без побочных эффектов). Если Docker или утилиты отсутствуют, установщик сообщает, что нужно поставить вручную.

## Параметры

`--profile`, `--dir` (по умолчанию `/opt/arklock`), `--data` (по умолчанию `/var/lib/arklock`), `--config`, `--project`, `--port`, `--url`, `--ref`, `--repo`, `--allow-unreleased`, `--yes`, `--dry-run`. Подробности: `./install.sh --help`.

## Первый вход

Откройте адрес из итога установки, создайте первую учётную запись, введите код настройки (он хранится в `arklock.env` как `BOOTSTRAP_TOKEN` и нужен только для первой записи), сохраните показанный **ключ восстановления**.

## HTTPS и reverse proxy

Приложение слушает только `127.0.0.1`; наружу смотрит Nginx с HTTPS.

**Автоматически** (профиль standalone, Debian/Ubuntu):

```bash
sudo ./install.sh --https letsencrypt --domain arklock.example.com --email admin@example.com
# или позже, на работающей установке:
sudo scripts/proxy.sh setup --domain arklock.example.com --mode letsencrypt --email admin@example.com
```

Режимы: `letsencrypt` (бесплатный сертификат Let's Encrypt; нужны публичное DNS-имя этого сервера и открытые порты 80 и 443; продление — таймером certbot с перезагрузкой Nginx), `self-signed` (закрытые сети и проверки; браузер предупредит, пока сертификат не добавлен в доверенные), `existing` (свой сертификат: `--cert`, `--key`; проверяется, что ключ подходит к сертификату и срок не истёк). Сценарий ставит пакеты `nginx` (и `certbot`), пишет `/etc/nginx/conf.d/arklock-<проект>.conf`, проверяет `nginx -t` (при ошибке возвращает прежнюю конфигурацию), записывает в `arklock.env` `APP_PUBLIC_URL=https://домен` и `TRUSTED_PROXY_HOPS=1` и перезапускает приложение. Настройка прокси: перенаправление http → https, HSTS, TLS 1.2/1.3, передача реального адреса клиента (`X-Forwarded-For` перезаписывается — подделать его нельзя), отключённая буферизация больших ответов, `client_max_body_size 32m` (вложения передаются частями).

Управление: `scripts/proxy.sh status` (конфигурация, `nginx -t`, срок сертификата, продление), `renew`, `remove`, `print` (вывести конфигурацию, ничего не меняя).

**Общий сервер (профиль shared-host)**: Nginx, уже обслуживающий другие сайты, не изменяется — `install.sh --https … --domain …` лишь создаёт пример конфигурации `nginx-arklock.conf.example` рядом с `arklock.env`; `scripts/proxy.sh print --domain …` печатает её, подключите результат сами. Если Nginx уже обслуживает другие сайты, `setup` отказывается работать без `ARKLOCK_PROXY_FORCE=1`.

**Проверено**: в CI на Ubuntu 24.04 — самоподписанный режим с настоящим Nginx (перенаправление, заголовки, `status`, повторная настройка, удаление); на Debian 12 — синтаксис конфигурации для Nginx 1.22 (`http2` в директиве `listen`). **Не проверено автоматически**: получение сертификата Let's Encrypt (нужны публичное DNS-имя и доступ из интернета) и продление certbot — используются стандартные команды `certbot certonly --webroot` и `certbot.timer`; перед боевым использованием выполните `scripts/proxy.sh setup --staging` (тестовый центр сертификации) и `certbot renew --dry-run`.

## Ограничения

- Образ собирается на сервере из исходного кода; публикация образов в GHCR и проверка digest — планируются вместе с релизами.
- Установка в закрытом контуре (локальный registry, офлайн-пакет) не реализована.
