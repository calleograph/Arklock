# Расширение для браузера и работа с телефона

## Расширение (Manifest V3)

Каталог `apps/extension`. Поиск записей по адресу страницы, заполнение формы входа, копирование, коды TOTP, генератор паролей.

### Сборка и установка

```bash
npm ci && npm run build            # собирает всё, в том числе apps/extension/dist
```

Chrome / Edge / Brave: «Расширения» → «Режим разработчика» → «Загрузить распакованное» → каталог `apps/extension/dist`.
Публикация в магазинах расширений не выполнялась.

### Вход

- **Почта и мастер-пароль** (и код второго фактора, если он включён). Ключи выводятся в браузере (Argon2id), серверу уходит только проверочное значение.
- **Токен API + мастер-пароль** — для учётных записей, входящих через SSO или каталог (создаётся в «Безопасность» → «Токены API»).
- Доступ к вашему серверу браузер запрашивает у вас явно, только для этого адреса (`optional_host_permissions`); `http://` допустим только для `localhost`.

### Что где хранится

- Сессия и ключи хранилищ — в `chrome.storage.session`: память браузера, на диск не пишется, очищается при закрытии браузера, по таймеру автоблокировки (по умолчанию 5 минут, настраивается) и кнопкой «Заблокировать». Контент-скрипты и страницы к ней доступа не имеют.
- Мастер-пароль и закрытый ключ учётной записи не сохраняются нигде. В `chrome.storage.local` лежат только адрес сервера, почта и время автоблокировки (проверено тестом).
- Подписи выданных ключей хранилищ проверяются по журналу ключей — как в веб-клиенте.

### Заполнение

- Выполняется **только по нажатию «Заполнить»** на текущей вкладке (разрешения `activeTab` + `scripting`); расширение не внедряет скрипты в страницы само.
- Запись предлагается для страницы, если узел совпадает (без `www`) или страница — поддомен узла записи; `evil-example.test` и `example.test.evil.test` для записи example.test не совпадают.
- Для не совпавшего узла и для понижения https → http перед заполнением запрашивается подтверждение.
- Заполняются только видимые поля; значения вставляются «как у пользователя» (события `input`/`change`), поддерживаются двухэтапные формы (сначала имя).

### Проверка

`apps/extension/test` (сопоставление адресов) и сценарий в настоящем браузере `e2e/extension.spec.ts`: вход (неверный и верный пароль), поиск записи для страницы, заполнение формы, TOTP, отказ при чужом сайте, генератор, блокировка, отсутствие секретов в локальном хранилище. Запуск: `EXT_TEST_HOSTS='http://127.0.0.1/*' npm run build -w @arklock/extension && E2E_EXTENSION=1 npx playwright test --project=extension` (нужен видимый браузер; в CI — под xvfb).

Не реализовано: автоматическое предложение сохранить пароль, заполнение по горячей клавише, Firefox (манифест V3 Firefox отличается), публикация в магазинах.

## Телефон: PWA

Веб-приложение устанавливается на главный экран (Chrome/Edge/Android: «Установить приложение», iOS Safari: «На экран “Домой”»): манифест, значки (в том числе маскируемый), отдельное окно без адресной строки.

- Service worker кэширует только статические файлы интерфейса (оболочку). Запросы `/api/`, страницы получения секрета `/h/` и любые не-GET запросы **не кэшируются**; тест проверяет, что в кэше нет ни одного адреса API.
- Без сети открывается сохранённая оболочка (данные при этом недоступны, так как ключи есть только на устройстве после входа).
- Интерфейс подогнан под узкие экраны: тест при ширине 390 px проверяет, что вход, сейф, форма и просмотр записи, «Безопасность», разделы администрирования, «Обновления» и «Состояние» не прокручиваются вбок.
- Автоблокировка и запрос мастер-пароля работают так же, как на компьютере.

Нативных приложений для iOS/Android нет.
