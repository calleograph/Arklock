# Arklock

**Arklock — корпоративный менеджер паролей с открытым исходным кодом.** Бесплатный, ориентирован на безопасность, самостоятельное развёртывание и централизованное управление доступом. Данные шифруются на стороне клиента, сервер хранит только шифртекст.

> **Статус: ранний прототип (0.1.0-dev).** Не используйте для хранения реальных секретов: криптографическая архитектура не проходила независимую проверку, а значительная часть функций ещё не реализована (см. таблицу ниже).

## Установка

Подробно — [docs/INSTALL.md](docs/INSTALL.md). Кратко (Ubuntu 24.04 или Debian 12, root):

```bash
curl -fsSLO https://raw.githubusercontent.com/calleograph/arklock/<тег-релиза>/install.sh
less install.sh                      # просмотрите установщик перед запуском
sudo bash install.sh --ref <тег-релиза>
```

Установщик по умолчанию берёт последний релизный тег и не исполняет содержимое ветки `main`. Он поддерживает два профиля: **standalone** (отдельный сервер) и **shared-host** (сервер с другими приложениями: чужие контейнеры, порты и настройки не затрагиваются). После установки откройте адрес из итога, создайте первую учётную запись по одноразовому коду настройки и сохраните ключ восстановления.

> Релизов пока нет. До первого релиза установка выполняется из клона репозитория: `sudo ./install.sh`.

## Обслуживание

```bash
sudo scripts/status.sh              # состояние
sudo scripts/verify.sh              # проверка установки
sudo scripts/backup.sh              # зашифрованная резервная копия
sudo scripts/restore.sh ФАЙЛ        # восстановление
sudo scripts/check-updates.sh       # есть ли новая версия
sudo scripts/update.sh              # обновление (с резервной копией и автоматическим восстановлением)
sudo scripts/rollback.sh            # откат (отказывает, если схема БД изменилась)
sudo scripts/diag.sh                # диагностический пакет без секретов
```

## Безопасность

Мастер-пароль и ключи никогда не покидают браузер: из пароля Argon2id выводятся независимые ключи шифрования и входа; закрытый ключ аккаунта хранится на сервере только в зашифрованном виде; каждая запись шифруется собственным ключом, привязанным к контексту (AAD). Резервные копии дополнительно шифруются ключом, который хранится отдельно. Подробности и известные слабые места — [docs/security/cryptography.md](docs/security/cryptography.md). Об уязвимостях сообщайте согласно [SECURITY.md](SECURITY.md).

## Разработка

Node.js 24+. `npm ci && npm run build`, проверки: `npm run format:check && npm run lint && npm run typecheck && npm test`; тесты в браузере: `npx playwright install chromium && npm run test:e2e`. См. [CONTRIBUTING.md](CONTRIBUTING.md). Изменения — [CHANGELOG.md](CHANGELOG.md).

## Известные ограничения

- Проверено на Ubuntu 24.04 (раннер CI). Debian 12, реальный сервер, перезагрузка во время обновления, нехватка места — не проверялись.
- Образ собирается на сервере; публикация образов в GHCR и проверка digest — запланированы.
- Нет остальных разделов административной панели (ресурсы, контейнеры, журналы, резервное копирование, диагностика, LDAP, SMTP); есть раздел «Обновления».
