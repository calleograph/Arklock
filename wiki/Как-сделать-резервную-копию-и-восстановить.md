# Как сделать резервную копию и восстановить

> Относится к версии 1.76.0 · проверено 2026-10-26 · уровень проверки 2 (задача CI `installer`); S3 — Scality CloudServer, SMB — Samba

*Тип страницы: практическое руководство.*

Для кого: системный администратор. Результат: зашифрованные копии по расписанию, проверенные на восстановимость, и знание порядка восстановления. Нужно заранее: установленный Arklock, root-доступ.

## Что входит в копию

Один файл `*.bak.gpg` (GnuPG, AES-256, парольная фраза из `BACKUP_KEY_FILE`) с дампом PostgreSQL (учётные записи, зашифрованные клиентом записи, зашифрованные закрытые ключи пользователей, настройки, журнал), файлом `arklock.env` и манифестом (версия, число миграций, контрольная сумма). Рядом лежит `*.bak.gpg.json` с контрольной суммой файла.

Зашифрованные файлы вложений (каталог `DATA_ROOT/blobs`) тоже входят в архив копии, а при восстановлении возвращаются на место (подтверждено чтением `scripts/backup.sh` и `scripts/restore.sh`, уровень 1).

Дамп восстанавливает доступ ко всем секретам: пользователи входят прежними паролями разблокировки сейфов.

## Ключ резервного шифрования

Установщик создаёт `/etc/arklock/backup.key` (права 600). Он хранится отдельно от копий.

> **Предупреждение.** Скопируйте `backup.key` в надёжное место вне сервера. Без него копии не расшифровать.

## Создать и проверить копию

```bash
sudo scripts/backup.sh [--keep 14] [--label имя]
sudo scripts/backup.sh --verify ФАЙЛ
sudo scripts/backup.sh --restore-test ФАЙЛ
```

Ожидаемый результат `backup.sh`: файл `*.bak.gpg` в `DATA_ROOT/backups` и сообщение об успешной проверке. `--keep N` оставляет N последних копий (по умолчанию 14).

`--restore-test` восстанавливает копию во временную базу `arklock_restore_test_<номер>`, сверяет число миграций, сообщает число учётных записей, сейфов, записей и ключей и удаляет временную базу. Рабочая база не меняется. Нужно столько же свободного места, сколько занимает рабочая база. Записи остаются зашифрованными: проверяется восстановимость, а не содержимое.

В панели: «Администрирование → Хранилища и резервирование → Резервные копии». Кнопка «Проверить» выполняет пробное восстановление.

## Восстановить на этом сервере

> **Предупреждение.** Восстановление заменяет текущую базу. Данные, записанные после копии, теряются. Скрипт сначала делает аварийную копию с меткой `pre-restore`.

```bash
sudo scripts/restore.sh ФАЙЛ [--yes]
```

Скрипт проверяет копию, сверяет версию миграций (копия новее приложения — отказ), требует подтверждение, пересоздаёт базу и запускает приложение. Файл `arklock.env` текущего сервера не заменяется.

## Перенести на новый сервер

1. Выполните `install.sh` на новом сервере (тот же профиль).
2. Скопируйте ключ резервного шифрования в `/etc/arklock/backup.key` (права 600) и файл копии в `DATA_ROOT/backups`.
3. Выполните `sudo scripts/restore.sh ФАЙЛ`.

Автоматически проверяется восстановление из удалённой копии на чистом сервере в CI; перенос с локальным файлом описан, но отдельно не проверяется.

## Копии на S3 и SMB

Копия шифруется до отправки, хранилище видит только шифртекст.

1. Откройте «Администрирование → Хранилища и резервирование → Резервные копии → Удалённое хранилище».
2. Укажите тип (S3-совместимое хранилище или SMB/CIFS), адрес, учётные данные, папку, число хранимых копий и автоматическую отправку.
3. Нажмите проверку соединения. Arklock запишет, прочитает, сверит и удалит пробный объект.
4. Сохраните настройки. Для сохранения и загрузки нужен пароль разблокировки сейфов.

Секреты подключения не хранятся в базе Arklock и не попадают в копии: помощник хранит их в `remote.conf` (права 600, владелец root).

Целостность: после отправки проверяется размер, затем копия читается обратно и сверяется SHA-256. Файлы больше 100 МиБ уходят многочастной загрузкой. После отправки остаются N последних копий этого проекта.

Из командной строки:

```bash
sudo scripts/remote.sh configure
sudo scripts/remote.sh test
sudo scripts/remote.sh list
sudo scripts/remote.sh push ФАЙЛ
sudo scripts/restore.sh --remote ИМЯ
```

### Восстановить на другом сервере из удалённой копии

1. `install.sh` на новом сервере.
2. Скопируйте `backup.key` в `/etc/arklock/backup.key`.
3. `sudo scripts/remote.sh configure` — введите адрес и учётные данные хранилища.
4. `sudo scripts/remote.sh list`, затем `sudo scripts/restore.sh --remote ИМЯ`.

## Расписание

Копии по расписанию создаёт помощник обновлений (раздел «Расписание» в панели копий). Если автоматическая отправка включена, каждая копия уходит на хранилище. При сбое отправки локальная копия остаётся, а панель показывает ошибку.

## Ограничения

- S3: подпись AWS Signature V4; проверено на Scality CloudServer. AWS S3, Ceph и облачные сервисы не проверялись.
- SMB: `smbclient`, шифрование SMB 3. Проверено на Samba. Windows Server и NAS не проверялись.
- Блокировки объектов (WORM) и версионирование хранилища из Arklock не настраиваются.
- Автоматического пробного восстановления по расписанию нет.

## Типичные ошибки

- Копия с другого сервера не проверяется: скопируйте на новый сервер `backup.key` исходного.
- Не хватает места: проверьте `df -h /var/lib`.

См. [Диагностика](Диагностика).
