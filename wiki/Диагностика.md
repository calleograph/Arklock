# Диагностика

> Относится к версии 1.84.0 · проверено 2026-10-28 · уровень проверки 1–2 (источник: `docs/TROUBLESHOOTING.md`, `docs/DIAGNOSTICS.md`, скрипты; решения автором не воспроизводились)

*Тип страницы: практическое руководство по симптомам.*

## Что собрать перед обращением

```bash
sudo scripts/diag.sh      # пакет без паролей и ключей
sudo scripts/status.sh    # состояние служб
sudo scripts/logs.sh      # журналы приложения (токены и пароли маскируются)
```

Приложите вывод к обращению в [issues](https://github.com/calleograph/Arklock/issues). Уязвимости сообщайте приватно ([политика](Лицензия-и-политика-безопасности)). Версию продукта смотрите в «Администрирование → Система → Обновления».

## Установка

**«ОС не поддерживается».** Поддерживаются Ubuntu 22.04/24.04 и Debian 12 (x86_64, aarch64). На другой системе используйте `ARKLOCK_ALLOW_UNSUPPORTED_OS=1` без гарантий.

**Порт занят.** Установщик выбирает свободный порт с 8080. Свой: `--port 8090`.

**Нет Docker или он не запущен.** В профиле `shared-host` установщик Docker не ставит. Проверьте `systemctl status docker`, запустите `sudo systemctl start docker`.

**Установка прервалась.** Повторите запуск: секреты, тома и данные не пересоздаются.

**Потерян код настройки.** Он в `/etc/arklock/arklock.env`, строка `BOOTSTRAP_TOKEN=`. Если в системе ещё нет пользователей, новый код выпустит `sudo scripts/admin-reset.sh new-setup-token`.

## Доступ к Arklock

**С другого компьютера страница не открывается.** По умолчанию приложение слушает только `127.0.0.1`. Запустите установщик снова с `--bind lan` или `--bind all`; данные сохранятся.

**Вход и регистрация по `http://192.168.x.x` не работают.** Браузер не даёт шифровать без HTTPS. Настройте HTTPS ([руководство](Как-настроить-HTTPS-и-reverse-proxy)).

**Вход возможен, но записи не появляются.** Обновите страницу. Проверьте время на сервере и в браузере (`timedatectl`): коды второго фактора зависят от времени.

**В журнале неверный IP клиента.** Проверьте `TRUSTED_PROXY_HOPS`: он равен числу прокси перед контейнером.

## Учётные записи и доступ

**Забыт пароль разблокировки сейфов.** На странице входа нажмите «Забыли пароль?» и введите ключ восстановления. Без пароля и ключа данные не открыть, администратор их не восстановит.

**Сотрудник не видит сейф, хотя ему назначили группу.** Ключ выдаёт участник с правом управления, когда открывает сейф. Пока такой участник не вошёл, статус «ключ ожидает выдачи». Дождитесь его входа.

**Нельзя отключить сотрудника: «корпоративный доступ под угрозой».** Он единственный хранитель ключа сейфов. Передайте права и ключ другому сотруднику. При срочном отзыве подтвердите риск.

**Исчез личный сейф после обновления.** Личные сейфы по умолчанию отключены; данные не удалены. Разрешите владельцу в «Настройки сервера → Основные → Личные сейфы» на время переноса.

**Администратор не может войти.** Оператор сервера: `sudo scripts/admin-reset.sh list`, затем `reset-mfa`, `end-sessions`, `enable`, `promote` или `chief` ([Справочник: скрипты](Справочник-скрипты)). Пароль разблокировки сейфов скрипт не сбрасывает.

**Вход временно заблокирован.** Подождите время, указанное в сообщении (по умолчанию окно 15 минут, 10 попыток).

**Не работает вход через LDAP или Active Directory.** Используйте «Проверить соединение» в разделе каталога; сверьте адрес, порт, сертификат и служебную запись. Приложите текст ошибки ([руководство](Как-подключить-LDAP-или-Active-Directory)).

**SAML: вход остановлен `idp_cert_expired`.** Все сертификаты провайдера истекли. Загрузите новые метаданные ([руководство](Как-настроить-SSO-OIDC-и-SAML)).

**Раздела «Импорт и экспорт» нет, сервер отвечает 403.** Раздел доступен только главному администратору.

## Обновления

**Обновление не проходит.** Установка и данные не меняются: Arklock возвращается на прежнюю версию или восстанавливает базу из копии. Причина — в разделе «Обновления» и в `sudo scripts/logs.sh`.

**«В каталоге программы есть локальные изменения».** Часто причина — адрес, вписанный в `compose.yaml` в версиях 1.0.x. Обновление переносит его в `APP_BIND` автоматически и сохраняет прежний файл в `/var/lib/arklock/config-backups/`. Если названы другие файлы, ничего не меняется: сохраните их копии, затем `git -C /opt/arklock checkout -- ИМЯ_ФАЙЛА` и повторите. Данные вне каталога программы не затрагиваются.

**«Адрес не совпадает».** В `APP_BIND` и `compose.yaml` разные адреса. Выберите нужный, запишите в `APP_BIND`, повторите.

**Помощник обновлений не запущен.** `sudo scripts/updater.sh repair`.

**Откат вручную.** `sudo scripts/rollback.sh` работает, если схема базы не менялась; иначе используйте `--with-restore` или `scripts/restore.sh`.

## Резервные копии

**Копия с другого сервера не проверяется.** Скопируйте `/etc/arklock/backup.key` исходного сервера на новый до загрузки копии.

**Ключ резервного шифрования потерян.** Копии с ним не открыть. Храните ключ отдельно от копий.

**Не хватает места.** Проверьте `df -h /var/lib` (`DATA_ROOT`). Срок хранения копий задаётся в настройках.

## Проверки состояния

| Команда | Что проверяет |
| --- | --- |
| `scripts/verify.sh` | контейнеры, API, версию, схему БД, права файлов, место |
| `scripts/smoke-test.sh` | основные сценарии без изменения данных |
| `scripts/repair.sh` | каталоги и права; перезапуск только с `--restart` |

В панели: «Администрирование → Система → Диагностика» со ссылкой на нужную настройку.
