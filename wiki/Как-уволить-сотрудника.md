# Как уволить сотрудника

> Относится к версии 1.79.0 · проверено 2026-10-27 · уровень проверки 2 (`offboarding.test.ts`, браузерные сценарии; 1500 записей — 6,3 с)

*Тип страницы: практическое руководство.*

Для кого: полный администратор. Результат: доступ сотрудника закрыт, сейфы переданы, составлен список паролей для смены. Нужно заранее: права полного администратора. Передачу владения выполняет только полный администратор.

## Шаги

1. Откройте «Администрирование → Пользователи и подразделения → Пользователи», найдите сотрудника и выберите «Уволить».
2. Прочитайте сводку: корпоративные сейфы сотрудника, число записей, сеансов, токенов API и внешних ссылок. Содержимое не показывается.
3. Для каждого сейфа, где сотрудник — единственный владелец, выберите нового владельца. Он должен уже входить в сейф и иметь его текущий ключ. Иначе сначала выдайте ему доступ в настройках сейфа.
4. Если сотрудник — единственный хранитель ключа, подтвердите риск.
5. Подтвердите увольнение.

Операция выполняется одной транзакцией: блокировка, завершение сеансов, снятие ролей, участия в сейфах, группах и пространствах, прямых назначений на папки и записи, отзыв токенов и внешних ссылок.

## Что сделать после

> **Предупреждение.** Сотрудник мог сохранить ключ сейфа и пароли из него. Увольнение не отменяет знание, которое он уже получил ([Как работает отзыв доступа](Как-работает-отзыв-доступа)).

1. Смените ключ шифрования сейфов из списка итога («Действия → Настройки сейфа»).
2. Смените пароли во внешних системах. По каждой записи, которую сотрудник мог видеть, в «Событиях безопасности» сейфа открыто событие «Требуется смена пароля» (высокий риск). Оно закрывается, когда пароль записи меняют в Arklock.
3. Следите за общим итогом в карточке сотрудника: «закрыто X из M · доступно вам N».

Личный сейф сотрудника остаётся нетронутым: администратор его не читает и не удаляет.

## Если нельзя отключить: «корпоративный доступ под угрозой»

Сотрудник — единственный хранитель ключа сейфа. Сначала передайте права и ключ другому сотруднику. При срочном отзыве подтверждение риска разрешает блокировку без удаления шифртекстов; факт записывается в журнал.

## Похожие случаи

События «смените пароль» открываются при любой потере доступа: удалении участника, запрете или удалении правила, исключении из группы, истечении срока правила или участия.

## Типичные ошибки

- Нельзя уволить главного администратора: сначала отзовите у него роль главного ([Справочник: роли и права](Справочник-роли-и-права)).
