Для кого: разработчик. Результат: проект собран, проверки проходят, изменение готово к предложению. Нужно заранее: Node.js 24 и npm 11, git.

## Собрать и проверить

```bash
npm ci
npm run build
npm run format:check && npm run lint && npm run typecheck && npm test
npm run check:private
```

Ожидаемый результат: все команды завершаются с кодом 0. Браузерные сценарии:

```bash
npx playwright install chromium
npm run test:e2e
```

> **Предупреждение.** Перед браузерными сценариями пересоберите проект (`npm run build`): версия сервера и веб-сборки должна совпадать, иначе тесты проверяют устаревшую сборку.

## Правила

1. Каждое изменение поведения сопровождается тестом и обновлением `PROJECT.md`, `HISTORY.md` и, для видимых изменений, `CHANGELOG.md`.
2. Версия — SemVer, единственный источник — файл `VERSION`.
3. Криптографический код: никаких собственных примитивов; изменение формата — только с новой версией формата и тестами совместимости.
4. В репозиторий нельзя добавлять секреты, `.env`, дампы базы, частные адреса и внутренние имена. Проверка: `npm run check:private` (и `node scripts/check-private-data.mjs --history` для истории).
5. Вклад принимается на условиях AGPL-3.0-only с подтверждением происхождения (Developer Certificate of Origin): `git commit -s`.
6. Оформление интерфейса подчиняется [дизайн-системе](https://github.com/calleograph/Arklock/blob/main/docs/DESIGN_SYSTEM.md): шкала текста 12/14/18 px, радиусы 6/10/12 px, высота поля 36 px, шрифты Onest и JetBrains Mono.

## Предложить изменение

1. Создайте ветку и внесите изменение вместе с тестами.
2. Выполните проверки из раздела «Собрать и проверить».
3. Откройте pull request в основной репозиторий. Опишите, что изменено и как проверено.

Исходники вики лежат в каталоге `wiki/` основного репозитория, поэтому правки документации проходят ту же проверку ([Сопровождение вики](Сопровождение-вики)).
