# Как обновить и откатить Arklock

> Относится к версии 1.83.0 · проверено 2026-10-28 · уровень проверки 2 (CI: задачи `update-flow` и `update-from-web`)

*Тип страницы: практическое руководство.*

Для кого: системный администратор. Результат: Arklock обновлён до нужной стабильной версии, прежняя версия доступна для отката. Нужно заранее: работающий помощник обновлений (`sudo scripts/updater.sh status`), свободное место, пароль разблокировки сейфов администратора.

Обновление меняет только Arklock. Оно не выполняет `npm update` и `apt upgrade` и не меняет мажорную версию PostgreSQL.

## Обновить из браузера

1. Откройте «Администрирование → Система → Обновления».
2. Нажмите «Проверить обновления». Проверка систему не меняет.
3. Прочитайте изменения из журнала изменений и число миграций.
4. Нажмите «Обновить до vX.Y.Z» и введите пароль разблокировки сейфов (подтверждение действует 5 минут).
5. Следите за этапами. Итог: «Обновление выполнено» либо «Не удалось собрать новую версию, работающая версия не затронута».

## Обновить из командной строки

```bash
sudo scripts/check-updates.sh
sudo scripts/update.sh [--ref vX.Y.Z] [--yes]
```

`check-updates.sh` возвращает код 10, если доступна новая версия, и 1, если репозиторий недоступен. Обновляются только релизные теги `vX.Y.Z`, а `VERSION` в теге обязан совпадать с тегом.

## Что происходит при обновлении

1. Проверка требований и отсутствия параллельных операций.
2. Получение тегов. При недоступности репозитория ничего не меняется.
3. Зашифрованная копия перед обновлением и её проверка. Без копии обновление не продолжается.
4. Образ работающей версии сохраняется под тегом `prev-<commit>`.
5. Новая версия собирается, пока старая работает.
6. Запуск новой версии, миграции, `verify` и `smoke-test`.
7. Запись результата в `DATA_ROOT/logs/updates.log`.

Если схема базы не менялась и обновление упало, возвращаются код и образ. Если миграции успели примениться, база восстанавливается из копии перед обновлением.

После успешного обновления остаются два образа: текущий и предыдущий. Остальные образы этого экземпляра и кэш сборки очищаются; чужие контейнеры и кэш при их наличии не трогаются.

## Автоматические проверки и установка

«Администрирование → Система → Обновления → Автоматические обновления».

- Проверка новой версии идёт каждые 30 минут и включена по умолчанию. Она ничего не устанавливает.
- Установка выключена по умолчанию. Включая её, укажите время (по часовому поясу сервера) и введите пароль разблокировки сейфов.
- Раз в сутки в заданное время ставится только новая **стабильная** версия. Повторной попытки в тот же день после сбоя нет.
- Без работающего помощника ничего не происходит.
- Отключить планировщик на уровне сервера: `AUTO_UPDATE=off`.

## Откатить

```bash
sudo scripts/rollback.sh [--with-restore]
```

Или кнопка «Откатить» в панели.

- Если схема базы не менялась, возвращаются код и образ.
- Если менялась, `rollback.sh` отказывается (код 3). С `--with-restore` база восстанавливается из копии перед обновлением.

> **Предупреждение.** `--with-restore` теряет данные, записанные после обновления.

## Что проверено и что нет

Проверено в CI: обновление с миграцией, отказ отката при изменённой схеме, откат с восстановлением, сбойная миграция, сбой сборки (работающая версия не затронута), недоступный репозиторий.

Не проверено: прерывание процесса посреди операции, нехватка места, перезагрузка во время обновления, проверка подписей тегов (`ARKLOCK_REQUIRE_SIGNED_TAGS=1`).

## Типичные ошибки

- «В каталоге программы есть локальные изменения» — [Диагностика](Диагностика).
- Помощник не запущен: `sudo scripts/updater.sh repair`.
