# Справочник: журнал событий

> Относится к версии 1.84.0 · проверено 2026-10-28 · уровень проверки 1–2 (список семейств из документации syslog и кода; полный перечень названий в коде `apps/api/src`, классификатор важности — `event-level.ts`)

*Тип страницы: справочник.*

Журнал действий доступен в «Администрирование → Безопасность → Журнал действий». Те же события уходят в syslog и вебхуки ([Как передавать журнал](Как-передавать-журнал-во-внешние-системы)).

## Поля события

| Поле | Значение |
| --- | --- |
| время | момент события |
| `actor` | пользователь или `operator` (действия `admin-reset.sh`) |
| тип | название события, например `entry.update` |
| `result` | `success` или `failure` |
| `target` | идентификатор объекта: `entry:<id>`, `vault:<id>`, `user:<id>` |
| метаданные | несекретные: `vault`, `ip`, число затронутых записей |

IP записывается только у событий входа. Названия записей и папок серверу неизвестны и в журнал не попадают.

## Семейства событий

| Семейство | Примеры |
| --- | --- |
| Вход и сеансы | `auth.login`, `auth.login.failed`, `auth.logout`, вход через каталог, SSO и SAML (`auth.saml.failed`, `auth.saml.revoked`, `auth.saml.logout`), второй фактор, PIN, ключи доступа, смена пароля, восстановление, токены API |
| Записи и папки | `entry.create`, `entry.update`, `entry.move`, `entry.delete`, `entry.restore`, `entry.purge`, `entry.revert`, `entry.fetch`, `entry.client.open`, `branch.create/update/delete/restore`, `attachment.add/download/delete` |
| Права и сейфы | `grant.put`, `grant.delete`, `vault.member.put/remove`, `vault.circle.put/remove`, `vault.keys.grant`, `vault.rotate`, `vault.owner.transfer`, `vault.personal.erase` |
| Импорт, экспорт, ссылки | `client.export`, `client.import` (формат и число записей), `client.export.begin`, `client.import.begin`, `handoff.create/open/revoke` |
| События безопасности | `signal.*`, `corporate.recovery.*`, увольнение, блокировка и разблокировка |
| Администрирование | `admin.*`: пользователи, группы, роли, главные администраторы (`admin.chief.appoint/accept/remove/offer/decline/cancel`), настройки (`admin.setting.change`), интеграции (`admin.saml.save`, `admin.saml.sp-cert`), копии, обновления, профиль сотрудника (`admin.user.profile`), `admin.user.offboard` |

События, помеченные «сообщено браузером» (`entry.client.open`, показ и копирование значения, импорт и экспорт), сервер доказать не может.

## Важность и серьёзность

В журнале есть фильтр важности и значок. Классификация общая с syslog: отказы и блокировки — «предупреждение», удаления и отзывы — «уведомление», остальное — «информация». Важность определяется по названию события.

## Срок хранения

По умолчанию — бессрочно. Можно задать срок не менее 30 дней («Сейфы и файлы»). Старые события удаляются при плановом обслуживании пачками; удаление записывается как событие и уходит в syslog.

## Выгрузка

Кнопка выгрузки создаёт CSV по тем же условиям и в том же порядке. Поиск: сотрудник (имя или почта автора и затронутой учётной записи), действие, объект, IP входа, период. Журнал сотрудника открывается из его карточки (`/admin/ledger?user=…`).

## Журнал объекта

У записи и папки есть вкладка «Журнал»: последние 100 событий объекта с поиском по действию, сотруднику, полю и дате.
