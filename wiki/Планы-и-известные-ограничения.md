# Планы и известные ограничения

> Относится к версии 1.86.0 · проверено 2026-10-28 · уровень проверки 0–1 (источник: `PROJECT.md`, `docs/REQUIREMENTS_ACCEPTANCE.md`). Планы не являются обязательствами.

*Тип страницы: справочник.*

Это единственная страница, где описаны планируемые функции. Журнал изменений — в [выпусках на GitHub](https://github.com/calleograph/Arklock/releases) и в `CHANGELOG.md` репозитория.

## Запланировано

| Что | Состояние |
| --- | --- |
| Несколько профилей хранилищ (вложения и копии) и перенос вложений между хранилищами | не начато как отдельный этап; требует проверки целостности |
| Проверки на реальных стендах (Active Directory, SSO, SAML, S3, SMB, Debian 12) | не выполнены |
| Независимый аудит криптографии | не проведён |
| Публикация расширений в магазинах | не выполнена |
| Подписанные сборки веб-клиента | задача релизного конвейера |

## Не реализовано и не планируется в текущем этапе

SCIM, нативные приложения iOS и Android, офлайн-установка, криптографическая изоляция отдельной записи внутри сейфа (нужны разные сейфы), правила автоматизации с произвольными выражениями, конструктор HTML-шаблонов почты.

## Известные ограничения

- Корпоративное восстановление работает только для заранее подключённых сейфов; получатель один.
- LDAP: нет вложенных групп, переноса идентичности при смене DN; предварительное создание учётных записей невозможно.
- Политики паролей проверяет только веб-клиент.
- Вебхуки без очереди на диске; перезапуск прерывает повторы.
- Подавление повторов уведомлений автоматизации хранится в памяти процесса.
- Таймеры (обновления, сверка LDAP, метрики) работают в каждом процессе приложения.
- Один случай падения живого сценария обновления в CI не получил установленной причины; при повторе его разбирают по трассе.
- Проверка экранным чтецом и измерение контраста WCAG не проводились.
- Шаблоны почты — только текст.
