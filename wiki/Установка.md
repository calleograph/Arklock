# Установка

> Относится к версии 1.86.1 · проверено 2026-10-29 · уровень проверки 2 (установка на Ubuntu 24.04 проверяется в CI; команды в этой вики автором не запускались)

*Тип страницы: практическое руководство.*

Для кого: системный администратор. Результат: работающий Arklock и первая учётная запись администратора.

## Что нужно заранее

- Сервер, подходящий под [системные требования](Системные-требования).
- Root-доступ.
- Решение, как сотрудники будут открывать Arklock: HTTPS на этом сервере, внешний reverse proxy или WAF либо пока только этот сервер (для проверки). Браузер шифрует мастер-пароль только по HTTPS или на `localhost`; про доступ по сети без HTTPS установщик скажет прямо.

## Шаги

1. Подключитесь к серверу по SSH под root или обычным пользователем с `sudo`.
2. Запустите установщик последнего выпуска:

   ```bash
   curl -fsSL https://github.com/calleograph/Arklock/releases/latest/download/install.sh | sudo bash
   ```

   Ожидаемый результат: установщик проверяет систему, определяет профиль и задаёт главный вопрос: **как пользователи будут открывать Arklock** (таблица ниже).

3. Выберите способ доступа. Если не уверены, нажмите Enter: по умолчанию выбирается безопасный «только этот сервер», домен не нужен.
4. Дождитесь конца установки. Установщик выполнит `scripts/verify.sh` и в итоге назовёт два состояния отдельно: **«Технически: готов»** (контейнеры работают) и **«Первый вход: готов / готов локально / не готов»**, а также напечатает адрес и **одноразовый код настройки**.
5. Откройте адрес из итога. Если первый вход «готов локально», выполните показанную команду SSH-туннеля и откройте `http://localhost:<порт>`. Если «не готов», итог называет команду, которая это исправляет (без переустановки).
6. Продолжите по странице [Первые шаги с Arklock](Первые-шаги-с-Arklock).

### Установка с проверкой установщика

Чтобы сначала прочитать установщик:

```bash
curl -fsSLO https://github.com/calleograph/Arklock/releases/latest/download/install.sh
curl -fsSLO https://github.com/calleograph/Arklock/releases/latest/download/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
less install.sh
sudo bash install.sh
```

Ожидаемый результат проверки: `install.sh: OK`.

### Как пользователи будут открывать Arklock

| Способ (`--access`) | Когда подходит | Что нужно | Что получится |
| --- | --- | --- | --- |
| Только этот сервер, `local` (по умолчанию) | Проверка, пилот, первая учётная запись до настройки HTTPS | Ничего: ни домена, ни сертификата | Приложение слушает только `127.0.0.1`. Первый вход на сервере или через SSH-туннель |
| HTTPS на этом сервере, `https` | Есть имя сервера | `--domain`, режим сертификата `--https letsencrypt\|self-signed\|existing` | Установщик настраивает Nginx и сертификат |
| Внешний reverse proxy или WAF, `proxy` | HTTPS уже есть на корпоративном прокси | Публичный адрес `--url https://…`, где стоит прокси (`--bind`) | Установщик сохраняет адрес и порт приложения и печатает, что настроить на прокси |

Примеры без вопросов:

```bash
# внешний прокси или WAF на другом сервере локальной сети
sudo bash install.sh --yes --access proxy --url https://arklock.example.com --bind lan

# HTTPS на этом сервере
sudo bash install.sh --yes --access https --https letsencrypt --domain arklock.example.com --email admin@example.com
```

Недостающее установщик называет до любых изменений: `--access proxy` без `--url`, адрес по `http://` вне localhost и подобные сочетания отклоняются с объяснением. Позже способ доступа меняется без переустановки и потери данных: `scripts/access.sh status | check | set local|proxy|https`. Подробности и список проверок — в `docs/INSTALL.md`.

Корпоративный адрес часто виден только из внутренней сети. Если с самого сервера его проверить нельзя, это не ошибка: `scripts/access.sh check` скажет «не удалось проверить» и попросит повторить изнутри сети.

## Что делает установщик

1. Проверяет ОС, архитектуру, память, место и права.
2. Выбирает профиль: `standalone` (отдельный сервер) или `shared-host` (на сервере уже работают другие приложения).
3. Ставит недостающие пакеты и Docker Engine — только в профиле `standalone`.
4. Подбирает свободный порт (с 8080), создаёт каталоги, файл `/etc/arklock/arklock.env` (права 600) со случайными секретами и ключ резервного шифрования `/etc/arklock/backup.key`.
5. Запускает PostgreSQL и приложение отдельным проектом Compose, применяет миграции.
6. Ставит помощник обновлений, выполняет проверку и печатает адрес и код настройки.

Повторный запуск безопасен: секреты, тома и данные не пересоздаются.

Установщик берёт последний релизный тег, а не ветку `main`. Готовый образ скачивается из `ghcr.io/calleograph/arklock:<версия>`, если метка коммита совпадает с загруженным кодом; иначе образ собирается на сервере. Отключить загрузку образа: `ARKLOCK_PULL_RELEASE_IMAGE=0`.

## Профиль shared-host

В этом профиле установщик не ставит Docker и пакеты и не меняет Nginx, чужие контейнеры и порты. Занятый порт не занимается: `--port` на занятый порт даёт отказ без побочных эффектов. Если нужных утилит нет, установщик скажет, что поставить вручную.

## Проверка успешной установки

```bash
sudo scripts/status.sh
sudo scripts/verify.sh
```

Ожидаемый результат: контейнеры работают, `verify.sh` завершается с кодом 0. Если нет — [Диагностика](Диагностика).

## Параметры установщика

`--profile`, `--dir` (по умолчанию `/opt/arklock`), `--data` (по умолчанию `/var/lib/arklock`), `--config`, `--project`, `--port`, `--bind`, `--access`, `--url`, `--https`, `--domain`, `--email`, `--tls-cert`, `--tls-key`, `--ref`, `--repo`, `--allow-unreleased`, `--yes`, `--dry-run`. Полный перечень: `./install.sh --help`. Описание — [Справочник: скрипты](Справочник-скрипты).

> **Предупреждение.** Не запускайте установку с `--ref main` и `--allow-unreleased` на рабочем сервере: ветка `main` не является выпуском.

## Типичные ошибки

- «ОС не поддерживается» и «порт занят» — в разделе «Установка» страницы [Диагностика](Диагностика).
- Код настройки потерян: он хранится в `/etc/arklock/arklock.env` в строке `BOOTSTRAP_TOKEN=`.
- Установка завершилась, но создать учётную запись не получается («браузер не разрешает шифрование на этом адресе»): вы открыли Arklock по `http://<IP>`. Выполните `scripts/access.sh status`: он покажет состояние и нужную команду. Быстрый путь без домена: SSH-туннель и `http://localhost:<порт>`.

## Ограничения

- Офлайн-установка (локальный реестр, офлайн-пакет) не реализована.
- Debian 12 и реальный сервер с перезагрузкой не проверялись.
