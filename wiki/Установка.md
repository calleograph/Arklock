# Установка

> Относится к версии 1.79.0 · проверено 2026-10-27 · уровень проверки 2 (установка на Ubuntu 24.04 проверяется в CI; команды в этой вики автором не запускались)

*Тип страницы: практическое руководство.*

Для кого: системный администратор. Результат: работающий Arklock и первая учётная запись администратора.

## Что нужно заранее

- Сервер, подходящий под [системные требования](Системные-требования).
- Root-доступ.
- Решение, откуда сотрудники будут открывать Arklock: только с сервера, из локальной сети или через reverse proxy. Для доступа из сети нужен HTTPS.

## Шаги

1. Подключитесь к серверу по SSH под root или обычным пользователем с `sudo`.
2. Запустите установщик последнего выпуска:

   ```bash
   curl -fsSL https://github.com/calleograph/Arklock/releases/latest/download/install.sh | sudo bash
   ```

   Ожидаемый результат: установщик проверяет систему, определяет профиль и задаёт вопрос, откуда открывать Arklock.

3. Выберите вариант доступа (таблица ниже).
4. Дождитесь конца установки. Установщик выполнит `scripts/verify.sh` и напечатает адрес и **одноразовый код настройки**.
5. Откройте адрес в браузере. Для адреса вида `http://192.168.x.x` вход не заработает — сначала настройте HTTPS ([Как настроить HTTPS](Как-настроить-HTTPS-и-reverse-proxy)).
6. Продолжите по странице [Первые шаги с Arklock](Первые-шаги-с-Arklock).

### Установка с проверкой установщика

Чтобы сначала прочитать установщик:

```bash
curl -fsSLO https://github.com/calleograph/Arklock/releases/latest/download/install.sh
curl -fsSLO https://github.com/calleograph/Arklock/releases/latest/download/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
less install.sh
sudo bash install.sh
```

Ожидаемый результат проверки: `install.sh: OK`.

### Откуда открывать Arklock

| Вариант | Параметр `--bind` | Адрес прослушивания | Когда подходит |
| --- | --- | --- | --- |
| Только этот сервер (по умолчанию) | `local` | `127.0.0.1` | Reverse proxy на этом же сервере |
| Локальная сеть | `lan` | IP сервера в локальной сети | Доступ с других компьютеров; нужен HTTPS |
| Все адреса | `all` | `0.0.0.0` | Прокси в Docker-сети; ограничьте порт фаерволом |
| Свой адрес | адрес | указанный адрес | Несколько сетевых интерфейсов |

Пример установки без вопросов, для reverse proxy на другом сервере:

```bash
sudo bash install.sh --yes --bind lan --url https://arklock.example.com
```

## Что делает установщик

1. Проверяет ОС, архитектуру, память, место и права.
2. Выбирает профиль: `standalone` (отдельный сервер) или `shared-host` (на сервере уже работают другие приложения).
3. Ставит недостающие пакеты и Docker Engine — только в профиле `standalone`.
4. Подбирает свободный порт (с 8080), создаёт каталоги, файл `/etc/arklock/arklock.env` (права 600) со случайными секретами и ключ резервного шифрования `/etc/arklock/backup.key`.
5. Запускает PostgreSQL и приложение отдельным проектом Compose, применяет миграции.
6. Ставит помощник обновлений, выполняет проверку и печатает адрес и код настройки.

Повторный запуск безопасен: секреты, тома и данные не пересоздаются.

Установщик берёт последний релизный тег, а не ветку `main`. Готовый образ скачивается из `ghcr.io/calleograph/arklock:<версия>`, если метка коммита совпадает с загруженным кодом; иначе образ собирается на сервере. Отключить загрузку образа: `ARKLOCK_PULL_RELEASE_IMAGE=0`.

## Профиль shared-host

В этом профиле установщик не ставит Docker и пакеты и не меняет Nginx, чужие контейнеры и порты. Занятый порт не занимается: `--port` на занятый порт даёт отказ без побочных эффектов. Если нужных утилит нет, установщик скажет, что поставить вручную.

## Проверка успешной установки

```bash
sudo scripts/status.sh
sudo scripts/verify.sh
```

Ожидаемый результат: контейнеры работают, `verify.sh` завершается с кодом 0. Если нет — [Диагностика](Диагностика).

## Параметры установщика

`--profile`, `--dir` (по умолчанию `/opt/arklock`), `--data` (по умолчанию `/var/lib/arklock`), `--config`, `--project`, `--port`, `--bind`, `--url`, `--https`, `--domain`, `--email`, `--tls-cert`, `--tls-key`, `--ref`, `--repo`, `--allow-unreleased`, `--yes`, `--dry-run`. Полный перечень: `./install.sh --help`. Описание — [Справочник: скрипты](Справочник-скрипты).

> **Предупреждение.** Не запускайте установку с `--ref main` и `--allow-unreleased` на рабочем сервере: ветка `main` не является выпуском.

## Типичные ошибки

- «ОС не поддерживается» и «порт занят» — в разделе «Установка» страницы [Диагностика](Диагностика).
- Код настройки потерян: он хранится в `/etc/arklock/arklock.env` в строке `BOOTSTRAP_TOKEN=`.

## Ограничения

- Офлайн-установка (локальный реестр, офлайн-пакет) не реализована.
- Debian 12 и реальный сервер с перезагрузкой не проверялись.
