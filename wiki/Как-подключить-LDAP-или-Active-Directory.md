# Как подключить LDAP или Active Directory

> Относится к версии 1.86.1 · проверено 2026-10-28 · уровень проверки 2 (`ldap.test.ts`, `ldap-ca.test.ts`, `directory-setup.test.ts` — LDAPS со своим центром сертификации, коды Active Directory). **Реальный каталог в проверках не использовался**, поведение на вашем каталоге нужно проверить на пилоте.

*Тип страницы: практическое руководство.*

Для кого: администратор и интегратор. Результат: сотрудники входят паролем каталога, группы каталога сопоставлены группам Arklock. Нужно заранее: адрес LDAPS-сервера, служебная учётная запись для поиска, базовый DN, при внутреннем центре сертификации — его сертификат. Права полного администратора.

## Принцип

Пароль каталога проверяет сам каталог. Arklock его не сохраняет. **Пароль разблокировки сейфов остаётся отдельным**: при первом входе сотрудник придумывает его, и браузер создаёт ключи. Отключение в каталоге закрывает доступ при следующей проверке входа или плановой сверке.

## Шаги

1. Откройте «Администрирование → Интеграции → Active Directory / LDAPS» и добавьте подключение.
2. Заполните поля:

   | Поле | Значение |
   | --- | --- |
   | Адрес | `ldaps://dc01.example.com:636` (рекомендуется) или `ldap://…:389` со StartTLS. `/` в конце убирается сам; ошибка показывается под полем с примером |
   | Сертификат CA | кнопка «Загрузить сертификат»: файл `.cer`, `.crt` или `.pem` (PEM или DER — без конвертации), можно цепочку |
   | Служебная запись | `CN=…` (полный DN), `svc-ldap@example.com` или `EXAMPLE\svc-ldap`; короткое имя дополняется доменом из Base DN. Пароль хранится зашифрованным и не возвращается |
   | Базовый DN | где искать пользователей |
   | Фильтр | по умолчанию `(&(objectClass=person)(\|(uid={u})(mail={u})(sAMAccountName={u})(userPrincipalName={u})))` |
   | Атрибуты | почта `mail`, имя `cn`; профиль: `title`, `department`, `telephoneNumber` |
   | Группы → круги | члены группы каталога автоматически входят в группу Arklock |

3. Нажмите «Проверить подключение» — сохранять перед этим не обязательно. Проверка идёт по этапам: DNS, соединение, TLS и сертификат, вход служебной записи, Base DN, фильтр, пользователи, группы. Ожидаемый результат: «Подключение работает»; при ошибке — этап и причина (например, «код 52e: неверное имя или пароль служебной записи»), ответ сервера — в «Подробностях».
4. Сохраните. Пометка «Есть несохранённые изменения» исчезнет. Затем нажмите «Найти пользователя» и убедитесь, что приходят DN, почта, имя и группы.
5. Привяжите группы каталога к группам Arklock (просмотр показывает пользователей, группы и OU; не более 100 записей).
6. Нажмите «Предпросмотр сверки»: он покажет, кого отключат, у кого изменятся группы и кто ещё не входил. Ничего не меняется.
7. Включите подключение и, если нужна, плановую синхронизацию; сохраните.

Незашифрованное `ldap://` отвергается, пока администратор явно не разрешит «только изолированная сеть». Отключение проверки сертификата — только для диагностики. Оба режима включает главный администратор с подтверждением паролем разблокировки сейфов, событие пишется в журнал. Пароль служебной записи при смене адреса сервера нужно ввести заново: сохранённый пароль на другой сервер не отправляется.

## Плановая сверка

Каждые 30 минут, если включена (по умолчанию выключена). Она блокирует учётные записи, исчезнувшие из каталога или отключённые в нём (флаг `ACCOUNTDISABLE`), завершает их сеансы и обновляет группы. Недоступность каталога не превращается в массовую блокировку: сохраняются прежние данные, показывается ошибка.

## Несколько подключений

Можно добавить несколько подключений; пользователь выбирает нужное при входе. Одинаковый DN в разных подключениях — разные идентичности. Подключение с зарегистрированными пользователями удалить нельзя, его можно отключить: сеансы его пользователей завершатся.

## Что нужно знать

- Существующая локальная учётная запись с той же почтой не присоединяется автоматически (ответ 409).
- Группы, привязанные к каталогу, управляются каталогом: ручные назначения делайте в отдельных группах.
- Членство в группе даёт роль группы в сейфе, но ключ сейфа выдаёт администратор сейфа; до этого сейф «ожидает ключ».
- Данные карточки сотрудника (ФИО, должность, подразделение, телефон) берутся из каталога и в панели не меняются; пустое значение поле не стирает.

## Ограничения

SCIM, вложенные группы и автоматический перенос идентичности после смены DN не реализованы. Предварительное создание учётных записей без клиентских ключей невозможно: пользователь подключается при первом входе. Просмотр каталога ограничен 100 записями.

## Типичные ошибки

- «Код 52e» на этапе входа: каталог отклонил имя или пароль служебной записи. Проверьте пароль и формат имени: короткое имя (`svc-ldap`) Active Directory не принимает — укажите `svc-ldap@example.com`, `EXAMPLE\svc-ldap` или полный DN (форма подсказывает, что будет использовано).
- «Сертификат не подтверждён»: загрузите корневой и промежуточный центры, которыми подписан сертификат контроллера домена (обычный `.cer` из центра сертификации подходит).
- «Сертификат выдан на другое имя»: подключайтесь по имени из сертификата, а не по IP-адресу.
- Вход через каталог не работает: используйте пошаговую проверку подключения ([Диагностика](Диагностика)).
