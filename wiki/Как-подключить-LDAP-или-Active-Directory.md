# Как подключить LDAP или Active Directory

> Относится к версии 1.88.0 · проверено 2026-10-28 · уровень проверки 2 (`ldap.test.ts`, `ldap-ca.test.ts`, `directory-setup.test.ts`, `directory-ad.test.ts` — тестовый каталог, отвечающий как Active Directory: RootDSE, вложенные группы, отключённые записи, код 52e). **Реальный каталог в проверках не использовался**, поведение на вашем каталоге нужно проверить на пилоте.

*Тип страницы: практическое руководство.*

Для кого: администратор и интегратор. Результат: сотрудники входят паролем каталога, группы каталога сопоставлены группам Arklock. Нужно заранее: адрес LDAPS-сервера, служебная учётная запись для поиска, базовый DN, при внутреннем центре сертификации — его сертификат. Права полного администратора.

## Принцип

Пароль каталога проверяет сам каталог. Arklock его не сохраняет. **Пароль разблокировки сейфов остаётся отдельным**: при первом входе сотрудник придумывает его, и браузер создаёт ключи. Отключение в каталоге закрывает доступ при следующей проверке входа или плановой сверке.

## Шаги

1. Откройте «Администрирование → Интеграции → Active Directory / LDAPS». Вверху видно состояние: подключение проверено или нет, вход сотрудников включён или нет, проверен ли вход.
2. **Шаг 1 — подключение.** Укажите адрес контроллера домена (`ldaps://dc01.example.com:636`), служебную учётную запись (`svc-ldap@example.com`, `EXAMPLE\svc-ldap` или полный DN) и её пароль. Если сертификат контроллера выдан внутренним центром, загрузите его файл `.cer`/`.crt`/`.pem`. Base DN можно не заполнять — он определится при проверке.
3. Нажмите **«Проверить подключение»**. Ожидаемый результат: «Подключение работает», Base DN подставлен. Если контроллер предъявляет самоподписанный сертификат, сверьте отпечаток и нажмите **«Доверять этому сертификату»**.
4. Нажмите **«Сохранить подключение»** — вверху появится «Подключение проверено».
5. **Шаг 2 — вход сотрудников.** Включите «Разрешить вход доменным учётным записям» и выберите, кто может входить: все действующие учётные записи или только участники групп (группу можно найти по имени). Сохраните.
6. В блоке **«Проверить вход сотрудника»** введите логин и пароль реального сотрудника. Ожидаемый результат: «Вход работает» и вверху «Вход сотрудника проверен». Учётная запись при этом не создаётся.
7. **Шаг 3 — дополнительно**, если нужно: сопоставление групп каталога группам Arklock, плановая синхронизация («Предпросмотр сверки» ничего не меняет), атрибуты карточки, фильтр, просмотр каталога.

Незашифрованное `ldap://` и отключение проверки сертификата — в свёрнутом блоке «Особые случаи»; их включает главный администратор с явным подтверждением в форме (флажок, без пароля). Пароль служебной записи при смене адреса сервера нужно ввести заново.

## Плановая сверка

Каждые 30 минут, если включена (по умолчанию выключена). Она блокирует учётные записи, исчезнувшие из каталога или отключённые в нём (флаг `ACCOUNTDISABLE`), завершает их сеансы и обновляет группы. Недоступность каталога не превращается в массовую блокировку: сохраняются прежние данные, показывается ошибка.

## Несколько подключений

Можно добавить несколько подключений; пользователь выбирает нужное при входе. Одинаковый DN в разных подключениях — разные идентичности. Подключение с зарегистрированными пользователями удалить нельзя, его можно отключить: сеансы его пользователей завершатся.

## Что нужно знать

- Существующая локальная учётная запись с той же почтой не присоединяется автоматически (ответ 409).
- Группы, привязанные к каталогу, управляются каталогом: ручные назначения делайте в отдельных группах.
- Членство в группе даёт роль группы в сейфе, но ключ сейфа выдаёт администратор сейфа; до этого сейф «ожидает ключ».
- Данные карточки сотрудника (ФИО, должность, подразделение, телефон) берутся из каталога и в панели не меняются; пустое значение поле не стирает.

## Ограничения

SCIM и автоматический перенос идентичности после смены DN не реализованы. Предварительное создание учётных записей без клиентских ключей невозможно: пользователь подключается при первом входе. Просмотр каталога ограничен 100 записями.

## Типичные ошибки

- «Код 52e» на этапе входа: каталог отклонил имя или пароль служебной записи. Проверьте пароль и формат имени: короткое имя (`svc-ldap`) Active Directory не принимает — укажите `svc-ldap@example.com`, `EXAMPLE\svc-ldap` или полный DN (форма подсказывает, что будет использовано).
- «Сертификат не подтверждён»: загрузите корневой и промежуточный центры, которыми подписан сертификат контроллера домена (обычный `.cer` из центра сертификации подходит).
- «Сертификат выдан на другое имя»: подключайтесь по имени из сертификата, а не по IP-адресу.
- Вход через каталог не работает: используйте пошаговую проверку подключения ([Диагностика](Диагностика)).
