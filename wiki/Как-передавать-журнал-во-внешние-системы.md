# Как передавать журнал во внешние системы

> Относится к версии 1.77.0 · проверено 2026-10-27 · уровень проверки 2 (`webhooks.test.ts`, тесты syslog). Реальные SIEM и приёмники не проверялись.

*Тип страницы: практическое руководство.*

Для кого: интегратор и специалист по безопасности. Результат: события журнала действий поступают в syslog и/или на вебхук. Нужно заранее: полный администратор; принимающая система.

## Syslog

«Администрирование → Интеграции → Журнал в syslog».

1. Укажите узел, порт и протокол: UDP, TCP или TLS (формат RFC 5424). При TLS проверка сертификата включена; отключайте её только на стенде.
2. При необходимости ограничьте отправку началом названия события (`auth.`, `admin.`). Пусто — все события.
3. Нажмите кнопку проверки. Arklock отправит пробное сообщение и покажет ошибку, если связь не удалась.
4. Сохраните. В панели видны счётчики «отправлено / не отправлено» и последняя ошибка.

В сообщении: время, пользователь (`actor`), название события, результат (`success` или `failure`), идентификатор объекта (`target`), несекретные метаданные. Серьёзность: отказы и блокировки — «предупреждение», удаления и отзывы — «уведомление», остальное — «информация». Паролей, ключей, секретов TOTP и содержимого записей нет. Названия записей и папок серверу неизвестны и в журнал не попадают.

Очереди на диске нет: недоставленные события остаются только в журнале действий Arklock.

## Вебхуки

«Администрирование → Интеграции → Вебхуки». До десяти вебхуков.

1. Нажмите добавление, укажите адрес HTTPS и, при необходимости, фильтр по началу названия события.
2. Сохраните секрет, который показан **один раз** (в базе хранится запечатанным; новый секрет выпускается кнопкой «Выпустить новый секрет»).
3. Проверьте доставку в «журнале доставки» (последние 100 доставок на вебхук, без тел сообщений).

Формат сообщения:

```json
{ "id": "…", "type": "admin.user.offboard", "at": "2026-10-18T09:00:00.000Z", "actor": "user:<id>", "target": "user:<id>", "detail": { "vaults": 2 } }
```

Подпись: заголовки `X-Arklock-Event`, `X-Arklock-Timestamp` (секунды), `X-Arklock-Signature: sha256=<hex>`, где подпись равна `HMAC-SHA256(секрет, "<метка>.<тело>")`. Получатель обязан сверить подпись и отбросить сообщения со старой меткой.

Защита и надёжность: только HTTPS; адреса во внутренних сетях, loopback и link-local запрещены; перенаправления не выполняются; три попытки (сразу, через 1 и 5 секунд). Очереди на диске нет: если Arklock перезапущен во время повторов, событие не будет доставлено повторно. Для строгого учёта используйте syslog.
