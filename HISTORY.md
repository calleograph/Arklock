# HISTORY — журнал разработки Arklock

Технический журнал. Записи только добавляются в конец. Изменения для пользователей — в [CHANGELOG.md](CHANGELOG.md).

---

## 2026-10-11 — Каркас, криптоядро, учётные записи и личный сейф

- Что сделано: монорепозиторий (npm workspaces, TypeScript strict); пакеты `@arklock/crypto` (AES-256-GCM, Argon2id, HKDF, ECDH P-256 sealed box, ключи хранилища и записи, ротация, ключ восстановления, смена пароля без перешифровки данных) и `@arklock/contracts`; API на Fastify + Drizzle (регистрация, вход с ограничением попыток, сессии, смена пароля, восстановление доступа, личный сейф, зашифрованные записи с оптимистичной блокировкой, миграции, PostgreSQL и PGlite); веб-клиент Vue 3 (ru/en, светлая и тёмная темы, генератор паролей, автоблокировка); Dockerfile и compose.yaml; CI; документы по архитектуре, криптографии и модели угроз.
- Решения: контекст шифрования кодируется JSON-массивом (исключает коллизии идентификаторов); реализация Argon2id сверена с эталоном OpenSSL (вектор RFC 9106); CSP разрешает WebAssembly для Argon2id.
- Результат: 18 тестов криптоядра, 33 теста API, 3 теста сканера, 2 сквозных сценария в браузере.

## 2026-10-11 — Лицензия, зависимости, контейнерная интеграция в CI

- Что сделано: лицензия AGPL-3.0-only (LICENSE, манифесты, проверка согласованности); обновлены `@fastify/static` и `drizzle-orm` (устранены уязвимости); контейнерная проверка в CI: регистрация, запись, пересоздание контейнеров, pg_dump/pg_restore, поиск секретов в слоях образа и логах.
- Результат: все задачи CI зелёные.

## 2026-10-11 — Установка, резервное копирование, обновление и откат (CLI)

- Что сделано: одноразовый код настройки первого администратора; `install.sh` (standalone и shared-host, идемпотентность, загрузка по тегу); библиотека сценариев; verify, preflight, status, logs, diag, smoke-test, repair; шифрованные backup/restore (GnuPG, ключ хранится отдельно); update, rollback, check-updates с автоматическим восстановлением. В CI: установка и повторная установка на чистом раннере, shared-host рядом с чужими контейнерами, повреждённая копия, восстановление после уничтожения БД, цепочка обновления на тестовых релизах (миграция, сбойная миграция, сбойная сборка, недоступный репозиторий).
- Исправлено по результатам тестов: ключи файлов состояния; идемпотентность записи конфигурации; наследование блокировки дочерними сценариями; приоритет явно заданного образа над файлом окружения; тег основного образа после отката.
- Результат: 9 задач CI зелёные.
- Не реализовано: помощник обновлений, веб-панель, GHCR и релизы; Debian 12 и реальный сервер не проверялись.

## 2026-10-11 — Помощник обновлений и страница «Обновления и версии»

- Что сделано: API `/admin/updates` и `/admin/reauth` (только администратор; токен повторного подтверждения пароля — 5 минут, привязан к сеансу; единственный запрос в обмен-каталоге создаётся атомарно); страница обновлений (версия, сборка, доступная версия, CHANGELOG, ход выполнения по этапам, история, проверка/обновление/откат); `scripts/updater.sh` (служба systemd с белым списком операций, строгим разбором запроса, стерильным окружением, пульсом, отметкой прерванных операций, перезапуском из свежей копии); этапы обновления в машиночитаемом виде; монтирование каталога обмена в контейнер; установщик ставит помощника.
- Исправлено по результатам тестов: ответ 401 на неверный пароль повторного подтверждения разлогинивал пользователя (теперь только код unauthorized); сообщения об ошибках 5xx для ожидаемых ошибок скрывались как internal_error.
- Результат (локально): 72 теста Vitest, 3 сценария Playwright (Edge), разбор запросов помощника — 14 проверок.
- Результат в CI (Ubuntu 24.04): все 10 задач зелёные, включая `update-from-web` (служба помощника, подделанные запросы отвергаются, проверка/обновление из браузера, релиз со сбойной миграцией восстанавливается).
- Найдено и исправлено в процессе: служба с ProtectHome не могла писать в /root (gpg, docker) — домашний каталог и GNUPGHOME перенесены в каталог данных; umask 077 установщика делал файлы обмена нечитаемыми для приложения; история записывалась после итогового статуса; прогресс показывал статус завершённой проверки вместо операции.
