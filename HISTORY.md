# HISTORY — журнал разработки Arklock

Технический журнал. Записи только добавляются в конец. Изменения для пользователей — в [CHANGELOG.md](CHANGELOG.md).

---

## 2026-10-11 — Каркас, криптоядро, учётные записи и личный сейф

- Что сделано: монорепозиторий (npm workspaces, TypeScript strict); пакеты `@arklock/crypto` (AES-256-GCM, Argon2id, HKDF, ECDH P-256 sealed box, ключи хранилища и записи, ротация, ключ восстановления, смена пароля без перешифровки данных) и `@arklock/contracts`; API на Fastify + Drizzle (регистрация, вход с ограничением попыток, сессии, смена пароля, восстановление доступа, личный сейф, зашифрованные записи с оптимистичной блокировкой, миграции, PostgreSQL и PGlite); веб-клиент Vue 3 (ru/en, светлая и тёмная темы, генератор паролей, автоблокировка); Dockerfile и compose.yaml; CI; документы по архитектуре, криптографии и модели угроз.
- Решения: контекст шифрования кодируется JSON-массивом (исключает коллизии идентификаторов); реализация Argon2id сверена с эталоном OpenSSL (вектор RFC 9106); CSP разрешает WebAssembly для Argon2id.
- Результат: 18 тестов криптоядра, 33 теста API, 3 теста сканера, 2 сквозных сценария в браузере.

## 2026-10-11 — Вложения (зашифрованные файлы)

- Что сделано: таблица `attachments`; хранилище файлов на диске (`BLOB_DIR`, в контейнере `/blobs`, на хосте `$DATA_ROOT/blobs`) с атомарной записью и точным контролем размера; маршруты регистрации, загрузки, скачивания и удаления; квоты (максимальный размер файла, квота хранилища) в настройках; шифрование на клиенте кусками по 1 МиБ (AES-256-GCM; в контексте — идентификатор вложения, номер куска, признак последнего: перестановка и усечение обнаруживаются); ключ вложения обёрнут ключом хранилища, имя и тип файла зашифрованы; ротация ключа хранилища перешифровывает файлы (подготовка новой версии файла, затем транзакция); сверка хранилища с базой (файлы-сироты, незавершённые загрузки); удаление файлов при окончательном удалении записи, ветви и хранилища; вкладка «Файлы» в записи; резервная копия включает каталог вложений, восстановление возвращает его.
- Решения: имя файла версии ключа входит в имя файла (`<id>.k<версия>`) — ротация не теряет данные при сбое между записью файла и транзакцией; превышение объявленного размера отбрасывается без обрыва соединения (клиент получает 400).
- Результат (локально): 8 тестов API вложений (включая ротацию и сверку), 2 теста криптографии, сценарий в браузере (файл виден на диске только как шифртекст; скачивается участником и после ротации ключа), интеграционная проверка `smoke-container.mjs` на собранном приложении.
- Проверка в CI (файлы после уничтожения каталога вложений и восстановления из копии) — результат фиксируется после прогона.

Секреты: не в базе данных и не в её копиях; панель передаёт их файлом 600 (значения в base64), помощник переносит в закрытый каталог, принимает в `remote.conf` (600, рядом с файлом окружения) и стирает файл; в параметрах процессов, журналах, снимках состояния секретов нет. Помощник: действия offsite_import/test/push/pull/verify/delete/refresh/clear; автоматическая отправка каждой новой копии (ручной и по расписанию) с ротацией на хранилище, явное сообщение, если отправка не удалась; снимок offsite.json. Панель: раздел «Удалённое хранилище» на странице копий (настройка, проверка, отправка, список, проверка, загрузка, удаление; опасные действия и сохранение — с мастер-паролем). Восстановление на другом сервере: `remote.sh configure` → `restore.sh --remote ИМЯ`. В CI: MinIO (настройка, проверка, отправка, многочастная загрузка, обнаружение подмены на хранилище, восстановление на «другом сервере» из удалённой копии), Samba (SMB), MinIO для действий помощника.
- Найдено в процессе: в bash 5.2 символ «&» в строке подстановки означает найденный текст — ETag в XML завершения многочастной загрузки превращался в мусор (исправлено); `sha256sum` с путём-аргументом может экранировать вывод — хэши считаются по стандартному вводу; тесты первоначально «зависали», потому что блокирующий запуск процесса не давал учебному S3-серверу из того же процесса отвечать.
