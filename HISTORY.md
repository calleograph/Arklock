## 2026-10-11 — Этап 1: рабочий каркас

- Что сделано: монорепозиторий (npm workspaces, TypeScript strict), пакет `@arklock/crypto` (AES-256-GCM, Argon2id, HKDF, ECDH P-256 sealed box, ключи хранилища и записи, ротация), `@arklock/contracts`, API на Fastify + Drizzle (health/ready/version, миграции, таблицы settings и ledger; PostgreSQL и PGlite), веб-оболочка Vue 3 (ru/en, светлая/тёмная темы), Dockerfile, compose.yaml, CI, сканер частных данных и секретов, документы по архитектуре, криптографии и модели угроз.
- Файлы: package.json, tsconfig.base.json, packages, apps, Dockerfile, compose.yaml, .env.example, .github/workflows/ci.yml, scripts/check-private-data.mjs, tests/scripts, docs, README.md, SECURITY.md, CONTRIBUTING.md, CHANGELOG.md.
- Результат: форматирование, линтер, сборка, типы и 22 теста проходят локально; собранный API с веб-клиентом запущен и проверен HTTP-запросами.
- Проблемы: Docker на машине разработки недоступен — контейнерная сборка не проверена.

## 2026-10-11 — Очистка публичных материалов, проверка криптоядра и Этап 2

- Что сделано:
  - Аудит публичных материалов: из документации убраны внутренние заметки и сравнительные материалы; расширен приватный список запрещённых шаблонов, который проверяет сканер (файлы и история git).
  - Проверка криптоядра: исправлена неоднозначность контекста шифрования (идентификаторы с двоеточием могли давать одинаковый контекст — теперь JSON-кодирование частей); ошибки расшифровки некорректного JSON сводятся к типизированной ошибке; добавлены ключ восстановления с контрольной суммой, смена пароля без перешифровки данных, доказательство владения ключом восстановления; Argon2id сверен с эталоном OpenSSL (вектор RFC 9106); тестов 18.
  - Этап 2 (API): регистрация, вход, ограничение попыток, сессии, смена пароля, восстановление доступа, личный сейф, зашифрованные записи с оптимистичной блокировкой; миграция БД переписана (до публикации); тестов 30 (проверена чувствительность теста доступа мутацией).
  - Этап 2 (клиент): регистрация с ключом восстановления, вход, разблокировка, автоблокировка, записи, генератор паролей, сеансы, смена пароля, восстановление; CSP разрешает WebAssembly для Argon2id.
  - Сквозные тесты Playwright (2 сценария) в Edge: найден и исправлен дефект — компонент входа не менял режим при переходе между /unlock и /login.
  - Проверка лицензий зависимостей (только разрешительные), оценка лицензий Apache-2.0 и AGPL-3.0 (решение за владельцем), документация API.
- Файлы: packages/crypto, packages/contracts, apps/api, apps/web, e2e, playwright.config.ts, scripts/check-licenses.mjs, .github/workflows/ci.yml, compose.yaml, .env.example, docs, README.md, PROJECT.md, CHANGELOG.md.
- Результат: форматирование, линтер, сборка, типы, 18 + 30 + 3 тестов и 2 сквозных теста в браузере проходят локально.
- Проблемы: Docker и CI не запускались; репозиторий на GitHub не создан; лицензия не выбрана; независимая проверка криптографии не проводилась.

## 2026-10-11 — Публикация, исправление CI, лицензия AGPL-3.0-only

- Что сделано: репозиторий создан владельцем, `main` опубликован (первый коммит 55dcbf8); первый прогон CI показал два дефекта, оба устранены: уязвимости зависимостей (`@fastify/static`, `drizzle-orm` — обновлены, аудит чист) и неверная передача переменных окружения в проверках контейнеров. Контейнерная сборка впервые подтверждена реальным запуском на раннере. CI расширен: полная интеграция контейнеров (регистрация, запись, пересоздание, pg_dump/pg_restore, поиск секретов в слоях и логах). Добавлена лицензия AGPL-3.0-only (LICENSE, манифесты, проверка согласованности в CI).
- Файлы: .github/workflows/ci.yml, apps/api/package.json, scripts/smoke-container.mjs, LICENSE, package.json (и манифесты пакетов), README.md, docs/development/licensing.md, CONTRIBUTING.md, scripts/check-licenses.mjs.
- Результат: все задачи CI зелёные.
- Проблемы: репозиторий закрытый, имя в GitHub записано как «Arklock».

## 2026-10-11 — Инфраструктурный рубеж 1: установка, копирование, обновление, откат

- Что сделано: одноразовый код настройки для первого администратора (в production без него администратор не создаётся); `install.sh` (standalone/shared-host, идемпотентность, самозагрузка по тегу); библиотека сценариев; verify, preflight, status, logs, diag, smoke-test, repair; шифрованные backup/restore (GnuPG, ключ отдельно); update/rollback/check-updates с автоматическим восстановлением. В CI добавлены проверки на чистом раннере: установка и повторная установка, shared-host рядом с чужими контейнерами, повреждённая копия, восстановление после уничтожения БД, цепочка обновления с тестовыми релизами (миграция, сбойная миграция, сбойная сборка, недоступный репозиторий).
- Найдено и исправлено тестами: ключи файлов состояния отвергались проверкой имён; повторная установка меняла порядок строк конфигурации; блокировка операций мешала дочерним сценариям; явное указание образа затиралось перечитыванием файла окружения; тег основного образа после отката указывал не на работающую версию (следующее обновление сохранило бы чужой образ).
- Файлы: install.sh, scripts/\*, scripts/lib/\*, tests/update/make-fixture.sh, compose.yaml, apps/api/src/routes/auth.ts, apps/api/src/config.ts, apps/web (код настройки), docs/INSTALL.md, UPDATE.md, BACKUP_AND_RESTORE.md, DIAGNOSTICS.md, README.md, PROJECT.md.
- Результат: 9 задач CI зелёные (в том числе установка, копирование, восстановление, обновление и откат).
- Проблемы: не реализованы помощник обновлений и веб-панель; Debian 12 и реальный сервер не проверялись; образы собираются на сервере, GHCR и релизы не настроены.
