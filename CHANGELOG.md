# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/), версии — SemVer.

## [Unreleased]

### Установка и обслуживание

- Установщик `install.sh` (профили standalone и shared-host, повторный запуск безопасен), одноразовый код настройки первого администратора.
- Зашифрованное резервное копирование и восстановление (`scripts/backup.sh`, `scripts/restore.sh`); ключ шифрования хранится отдельно.
- Обновление и откат из командной строки (`scripts/update.sh`, `scripts/rollback.sh`, `scripts/check-updates.sh`) с копией перед обновлением и автоматическим восстановлением при сбое.
- Диагностика: `verify`, `preflight`, `smoke-test`, `status`, `logs`, `diag`, `repair`.
- Лицензия AGPL-3.0-only.

### Обновления из веб-интерфейса

- Страница «Обновления и версии» для администратора: установленная и доступная версии, изменения, ход выполнения, история; проверка, обновление и откат с повторным подтверждением мастер-пароля.
- Помощник обновлений (служба systemd) с ограниченным набором операций; веб-приложение не получает доступ к Docker.

### Менеджер паролей

- Общие хранилища с ролями (владелец, администратор, редактор, читатель, ограниченный), круги, права на папки и записи с наследованием, сроком и отзывом; ротация ключа после отзыва доступа.
- Ключи хранилища выдаются подписанными; журнал ключей и закрепление открытых ключей защищают от подмены ключа сервером.
- Папки любой вложенности (названия зашифрованы), типы записей, теги, избранное, поиск и фильтры, история изменений с восстановлением, корзина, групповые операции.
- TOTP-коды, генератор паролей и парольных фраз, оценка стойкости.
- Импорт CSV; экспорт CSV, JSON и зашифрованный; инспектор безопасности паролей (слабые, повторяющиеся, старые, скомпрометированные) без передачи паролей на сервер.
- Ссылки передачи секрета: временные и одноразовые, ключ только во фрагменте адреса, необязательная кодовая фраза.
- Вложения: файлы шифруются в браузере, сервер хранит только шифртекст; квоты; входят в резервные копии.
- Двухфакторная аутентификация (TOTP) с QR-кодом и одноразовыми резервными кодами; политика обязательного MFA (для администраторов или для всех); сброс фактора администратором.
- Токены API (только чтение / чтение и запись, срок, отзыв) и консольный клиент `arklock` (list, get, totp, add, generate); токены не открывают данные.
- Панель администрирования: обзор, ресурсы, контейнеры, резервные копии (создание, проверка, скачивание, восстановление, расписание), системные журналы, хранилища со сверкой, диагностика, сертификаты, почта (SMTP) с тестовым письмом.
- Вход через каталог LDAP / LDAPS / Active Directory: отдельный мастер-пароль для шифрования, привязка групп к кругам, синхронизация и блокировка отключённых в каталоге.
- Единый вход через OpenID Connect (PKCE, проверка подписи и утверждений id_token, ограничение доменов).
- Расширение для браузера (Manifest V3): поиск по адресу страницы, заполнение формы, TOTP, генератор.
- Установка на телефон (PWA) и адаптивная вёрстка.
- Экспорт журнала событий в syslog (RFC 5424; UDP, TCP, TLS) с фильтром по префиксам.
- Ключи доступа (WebAuthn / аппаратные ключи) как второй фактор.
- Приглашения по одноразовой ссылке (в том числе при закрытой регистрации) и уведомления владельцу учётной записи о событиях безопасности по почте.
- Политика паролей организации (длина, виды символов): проверка при сохранении записи, подсказка генератору, отдельная категория в инспекторе.
- Вложения любого размера: шифрование и загрузка по частям, потоковое скачивание, ротация ключа без загрузки файла в память.
- Настраиваемые роли: полномочия, наследование, явные запреты, временный доступ, делегирование разделов панели; проверки на сервере.
- Вход по SAML 2.0 (поставщик услуг): настройка в панели, импорт метаданных, проверка сертификатов, подписанные и зашифрованные утверждения, сопоставление групп кругам, единый выход по запросу провайдера, привязка входа к браузеру.
- Удалённое хранилище резервных копий (S3-совместимое и SMB): настройка в панели, проверка соединения, автоматическая отправка и ротация, контроль целостности, секреты вне базы данных, восстановление на другом сервере (`restore.sh --remote`).
- Расширение: создание и изменение записей, обновление списка, обработка отзыва доступа; сборка и проверка для Firefox.
- Argon2id в Web Worker.
- Административный раздел: пользователи, круги, настройки (регистрация, срок корзины, пароли, файлы, адрес проверки утечек), журнал аудита.

### Добавлено

- Монорепозиторий (npm workspaces, TypeScript strict), CI в GitHub Actions (проверки, браузерные тесты, аудит зависимостей и лицензий, сканирование секретов, сборка контейнера).
- `@arklock/crypto`: AES-256-GCM, Argon2id, HKDF, ECDH P-256 sealed box, иерархия ключей хранилища и записи, ротация, ключ восстановления, смена пароля без перешифровки данных.
- API (Fastify): система (`/health`, `/ready`, `/version`), регистрация, вход с ограничением попыток, сессии, смена пароля, восстановление доступа, личный сейф и зашифрованные записи с контролем конфликтов; миграции Drizzle; PostgreSQL и встроенный PGlite.
- Веб-клиент (Vue 3, Pinia, Tailwind, vue-i18n ru/en, светлая и тёмная темы): регистрация с ключом восстановления, вход, разблокировка и автоблокировка, записи, генератор паролей, сеансы, смена мастер-пароля.
- Сквозные тесты в браузере (Playwright).
- `Dockerfile` и `compose.yaml` (непривилегированный пользователь, read-only rootfs, БД во внутренней сети).
- Сканеры частных данных, секретов и лицензий зависимостей.

### Исправлено

- Идентификаторы с двоеточием могли давать одинаковый контекст шифрования у разных записей — контекст кодируется однозначно.
- Неизвестные пути `/api/…` при включённой раздаче интерфейса возвращали HTML вместо JSON-404.
- Компонент входа не менял режим при переходе между экранами входа и разблокировки.
